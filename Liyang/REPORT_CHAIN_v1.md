## 6. 口径问题（必须和读数一起看）

1. **抽取器只覆盖合成句式，1.0 是能力上限，不代表真实表现。** 版本事件抽取是按 HMB chain 合成器的句式写的。难扰动 100% 时抽取完全失效，ng+chain 和 ng 逐题相同。目前在真实对话或非合成语料上的表现**没有任何读数**。
2. **泄露**：骨架阶段（be73847）为了核对抽取，看过**含 test 文档的生成日志**（`keys/synth_log.json`，87 条链逐事件比对），之后又按这次核对修正了抽取（属性懒匹配、括号内逗号）。所以 test 读数不是严格的保留集读数。
3. **机械读者是自研的**（`lingshu_ng.chain.read_material`）。旧的 item5_reader 读数用的是另一套读者，**不能直接和本报告比较**。各臂在本报告内部共用同一个读者，相互比较是公平的。读者和 chain 出自同一作者，对 chain 的材料形态可能有利。
4. **v2–v5 是在自建扰动 dev 上调的**：扰动生成器 `perturb.py` 是我方写的，dev 和 test 用的是同一个生成器、同一族句式。test 扰动读数只能证明「对这一族改写稳健」，不能推广到别的写法。v3 难扰动 50% 在 dev 上 0 负、在 test 上 14 负，说明 dev 上调出来的结论会过拟合。
5. **跨命名空间同名实体没有消歧**：名字表按子串定位，两个命名空间里出现同名实体时可能串账。HMB chain 轨里没有这种题，所以读数没有暴露这个问题。
6. C 档饱和，K 档是唯一有区分度的预算。LLM 历史题的优势不显著。小样本只有 47/59 题。
