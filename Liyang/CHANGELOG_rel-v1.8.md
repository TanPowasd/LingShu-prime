# CHANGELOG rel-v1.8（gen-r10：英文可选语义第二路 F3 的带模型查询延迟修复——rel-v1.5 未验收项）

相对上次推送版（Liyang/ = rel-v1.7，LingShu-prime 4cc01a25 / 发布树 rel-v1@b60a5915）的增量升级：**只改带模型（注入 bge-small-en）时的查询时延，不改任何名次与分数**。
无模型路径、中文通路、版本链均未改，回归门逐题相同。

## 为什么要这一版
rel-v1.5 把 F3（ColBERT 式 MaxSim 前 20 精排 + 问句路由 BGE 查询前缀）设为带模型缺省时，**带模型查询延迟没有验收**。r10 按 PREREG_GEN_v3 修订 11 R11.2 补测：
rel-v1.5–v1.7 的带模型缺省 B15 热 p95 ≈ **5.7×** R7（r7 带模型配置），冷首查 p95 ≈ **9.8×**——MaxSim 在查询时为前 20 名逐条现算逐词向量，且 20 次小矩阵乘在机器繁忙时被 OpenBLAS 多线程唤醒拖慢。这超出 R11.2 写死的 1.5× 硬门，是 v1.5–v1.7 的真实缺陷。

## 改了什么（三个纯时延件，均有逐位相同测试）
- **F3L**：写入时同一次前向顺带保存逐词向量（逐位等于查询时现算），按字节预算 LRU（`LINGSHU_NG_EMBED_TOKVEC_MB`，缺省 256；0 = 关，退回现算）。
- **F3P**：召回开始即后台线程预取稠密查询向量与 MaxSim 查询逐词向量，与词面通路并行（预取失败只是不省时，融合照常现算）。
- **F3T**：MaxSim 矩阵乘期间把 numpy 自带 OpenBLAS 线程数临时设 1（ctypes；找不到函数则不动；`LINGSHU_NG_BLAS1=0` 关）。OpenBLAS 只按输出行列切分线程、不改累加次序 ⇒ 逐位相同（`test_blas1_bitwise`）。拒绝的替代：把 20 段拼成一次矩阵乘（300 次随机试验 9 次不逐位相同）。
- 另：**F4 说话人意图先验**代码随附（`lingshu_ng/speaker.py`，`sp`/`sp_n`/`sp_win`），**缺省关**（sp = 0，逐位不变）。F4 冻结配置 sp 0.5 / sp_n 20 / sp_win 2 正在新未暴露保留集 H-CM10 上判定，**本版不据此改缺省**；判定结果见下一版 CHANGELOG 或 PREREG_GEN_v3 修订 11g。
- 测试：`tests_ng/test_tokvec_pre.py`（F3L/F3P/F3T 逐位核对，钉墙钟与随机 id）、`tests_ng/test_speaker_prior.py`（F4 缺省关逐位不变 + 规则单测）。

## 延迟验收（PREREG_GEN_v3 R11.2 协议，写死的硬门：热 p95 与冷首查 p95 均 ≤ 1.5 × 旧树 R7）
同一批 job（已暴露 cm8_dev 前 40 + lme_dev 前 10，W0），各臂独立子进程 ABAB 交替 2 轮，G1_FROZEN_CLOCK=1，单线程打分进程。读数 `bench_gen/out/r10_lat_f3t.json`：

| 臂 | 热 p50 | 热 p95 | 冷首查 p50 | 冷首查 p95 | 对 R7 热/冷 p95 |
|---|---|---|---|---|---|
| R7（旧树，参照） | 64.1 ms | 152.9 ms | 72.0 ms | 284.5 ms | 1× |
| **本版缺省 B15L（= F3 + F3L + F3P + F3T）** | 72.3 ms | **141.2 ms** | 77.6 ms | **263.1 ms** | **0.92× / 0.92×** ✔ |
| F4ub（B15L + F4 最贵形状，未进缺省） | 84.7 ms | 173.8 ms | 102.5 ms | 275.5 ms | 1.14× / 0.97× ✔ |

- 参照（F3T 之前一次读数，`r10_lat_main_preF3T.json`，同协议、负载不同）：rel-v1.5 缺省 B15 热 p95 813.8 ms / 冷 p95 4304 ms，即对 R7 **5.7× / 9.8×**；仅 F3L+F3P 时 1.62× / 1.12×（热仍未过）。
- 照实：两次读数在不同机器负载下测得（2 核，他线并行），倍数可比、绝对毫秒不可直接比；本版对 R7 的 0.92× 是同一次交替运行内的比值。
