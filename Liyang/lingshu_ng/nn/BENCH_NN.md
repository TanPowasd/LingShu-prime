# BENCH_NN · 旧 lingshu.nn vs lingshu_ng.nn

数据：`lingshu_ng/nn/BENCH_NN.json`（`python tests_ng/nn/bench_nn.py merge` 由 `tests_ng/nn/bench_parts/*.json` 汇总；
每节带 `when` 时间戳）。环境：2 核共享沙箱，`OPENBLAS_NUM_THREADS=1`，耗时为多次重复中位数。
“旧”= 本仓 `lingshu.nn`（已含 15:38–15:51 的旧线修复）；`gen_base` 另列上游基线 2bb8291（`LEGACY_ROOT`）。

代码版本：forward / equiv / gen 三节在 18:06–18:11 测量，其后 nn 提交（cabb06b、c71eace、3432e1c）只改
`search.py / multimodal.py / compat/hex_text.py / infogap.py`，不在这三节的路径上；train_step / text_search /
determinism / accuracy 在 3432e1c 之后（18:21–18:44）测量。accuracy legacy-legacy 运行时有其他测试并行，
其 `train_s` 偏高，只看准确率。

逐项相同（0 个参数不同）；旧 46.9 s → ng 0.45 s。

上游 1.0 的兑现率不可信：其验证器对 6 类坏画笔全部放行（不读像素）。ng 兑现率是“从成图像素读回”的口径，

画笔改 solid 后它本来就该通过。
