## 1. 三层架构与环境身份

| 层 | 内容 | 版本化对象 |
|----|------|-----------|
| 协议层 | 任务、流程、失败条件、评分规则 | 协议 ID + 版本 |
| 执行证据层 | 环境配置 ID、运行记录、原始产物 | run_id |
| 报告层 | 由证据层计算得出，禁止手改 | 报告 ID + 版本 |

**环境配置 ID**：每次正式运行生成一个不可歧义的配置 ID，内容清单至少含：DSH 版本、宿主版本、OS、模型+模型版本+采样参数、依赖锁、权限清单、外部服务清单+版本日期。**单一版本字符串不够，禁止只靠它描述环境。**

**插件身份按交付形态分**：源码版（commit SHA）/ 发布包版（包版本+哈希）/ 远程服务版（服务端点+观测日期）。无源码的插件标"无 commit 可观测"，**禁止虚构版本号**；不可得字段要注明它限制了什么结论。

**版本绑定必须追溯到 run 记录**，不是报告里列四个版本号就完事。

## 2. 结果判定：五种状态，判定算法固定

| 状态 | 判定（预注册阈值 + 预定统计方法） |
|------|------|
| ✅ 真有用 | 数据、计算、有效样本及精度检查通过，且区间下界 > 最小有意义阈值 |
| ❌ 帮倒忙 | 数据、计算、有效样本及精度检查通过，且区间上界 < −可接受退化边界 |
| ➖ 没啥差别（后台：实际等效） | 精度门槛满足，且区间完全落入预设等效范围；不表示绝对零差异 |
| ❓ 还说不准（后台：证据不足） | 有效实验中，无法满足正贡献、负贡献或实际等效条件；包括跨单侧阈值、区间边界相等、精度不足等情况 |
| 🚧 没法测 | 安装失败 / 环境不支持 / 任务不适用——**必须分别记录原因** |

**铁规**：
- 3 次重复是**最低门槛不是统计充分性证明**；正式结论还须满足预注册精度和有效样本要求。首轮固定样本量，达不到就标“还说不准”；要续采须另立协议，不反复查看普通 95% 区间直到出现好结果
- **"实验无效"与"插件表现差"分开**：判分器故障、环境异常 → 该次运行作废重跑（留痕），不给插件记失败
- 多重比较：预注册**主要指标（唯一进判定）/ 次要指标（参考）/ 汇总方法**，禁止事后挑有利结果

**统计方法按指标类型固定**（不许执行者自选）：

| 指标类型 | 方法 |
|----------|------|
| 配对连续分数 | 对配对差值估区间（bootstrap，固定种子与次数） |
| 配对二元任务成功率差 | 对每个配对任务记录装与不装的 0/1 结果，使用预先冻结并经过边界测试的配对比例差区间实现；实现必须写明公式、输入、边界和参考结果。同一场景内的题目或重跑有关联时，先按场景聚合再估计区间，不直接套普通二项区间。实现未经验证时不生成正式标签 |
| 稀有安全事件 | 报告“测了 N 次、观察到 k 次”；k=0 不等于风险为零。仅在预先说明独立试验及抽样假设时给统计上限；定向攻击题库只报覆盖和观察，不估真实事故发生率 |
| 人工评分 | 预注册评分尺度 + 分歧处理规则 + 一致性统计 |


### 2.3 判定规范模板（每能力域一份，冻结后不得临场发挥）

每个能力域上线前必须冻结一份判定规范，包含六要素，**全部写死后才允许产生正式结论**：

1. **主要指标**（唯一进入五状态判定）
2. **次要指标**（报告展示，不进判定）
3. **安全否决条件**（独立通道，见 §4）
4. **区间算法**（指定到具体方法，不许执行者自选）
5. **停止规则**（固定样本量 + 外部故障补跑上限 + 仍不精确时的处理）
6. **五状态映射**（阈值数值化）

**工具型插件的组合规则**（防"总榜不错但恢复差"式的判定漂移）：

```
能力结论：按任务正确性的五状态规则计算，不能被安全标签覆盖；但只有达到该能力域的发布门槛，才可进入正式榜。
推荐资格：已确认严重安全事件 → 暂停当前版本推荐；未确认 → 调查中。
效率与可恢复性：独立报告，不参与抵消安全事件，不合成能力总分。
页面先提醒安全风险，再展示保留下来的真实能力结果。
```

**附：记忆域判定规范 v0（待校准样例，不是已验证标准）**

| 要素 | 启动候选值 |
|------|--------|
| 主要指标 | 考卷 B 加权分（配对差值） |
| 次要指标 | 来源定位正确率、事实支持率、写入耗时；不把逐字复述当作来源正确的必要条件 |
| 安全否决 | §4 六威胁 + 确认门槛分级表 |
| 区间算法 | 按独立场景聚类的配对差值 percentile bootstrap，B=10000；先在场景内汇总重复运行，再重采样场景；种子取冻结的 analysis_id 的 SHA-256 前 8 字节（无符号大端整数），报 95% 区间；算法和实现版本写入记录 |
| 单组成功率 | 在题目可视为独立时，使用预先指定的二项区间；零成功报“0/k + 95% 上限” |
| 停止规则 | 首轮使用固定样本量：测试前写明独立场景数和重跑数，一次性完成后判定；建议至少 8 个独立场景、每场景至少 3 次配对重跑。精度目标为区间半宽 ≤5 分；不足时输出“❓证据不足”，不因中途看到好结果而提前停止 |
| 五状态映射 | 最小有意义提升 +5 分；可接受退化 −5 分（首域试跑值，校准后冻结） |

### 2.4 精确映射与独立单位

设主要指标差值区间为 `[L,U]`，正向门槛为 `a>0`，可接受退化幅度为 `b>0`，半宽为 `(U-L)/2`。

1. 数据或算法检查失败：运行状态为“实验无效/待重跑”，不输出能力五状态。
2. 安装失败、任务不适用或无法满足环境要求：输出“没法测”并附原因。
3. 算法尚未完成校验、证据缺失或结果无法计算：阻止正式分析，发布状态为“待验证/待修复”，不能生成数值区间和正式能力标签。若实验数据有效、计算已校验，但有效样本或精度不足，输出“还说不准”。
4. 在精度门槛满足的前提下，`L>a`：真有用；`U<−b`：帮倒忙。
5. 在精度门槛满足的前提下，`L>−b` 且 `U<a`：没啥差别（本次范围内实际等效，不是绝对一样）。
6. 其余全部为“还说不准”，包括区间刚好等于阈值。

首域采用 `a=b=5` 分，满分 100，半宽要求 ≤5 分。数值是启动试跑候选；只有完成校准、任务清单和权重冻结，才成为正式域规范。若尚未完成，报告标“方法试验”，不能把候选值称为正式冻结值。

独立单位是不同事实组合/项目/叙事的场景，不是同一历史里的每张卡。重跑测的是运行波动，不等于增加了独立语料。按场景重采样，保留场景内配对和全部题目；禁止把 89 张卡直接当作 89 个独立样本。场景不能合理分组时，报告只对这份固定材料成立，不生成跨场景正式结论。

bootstrap 的分层权重、场景聚合顺序、百分位计算方式、随机数生成器和库版本须在 analysis manifest 中登记；校验零方差、小样本和全成全败边界。极少场景下窄区间不代表充分证据。单组零事件的风险上限只在明确独立试验假设下计算；定向攻击集合不能估计真实世界事故发生率。

### 2.5 正式榜的额外门槛

五种结果先说明这一次实验看到什么；能不能进正式榜，还要再看：题集已正式冻结、判分器和区间算法已通过回归、独立场景和样本计划达到该域要求、报告证据完整、独立复核完成。未达工程门槛时，只发布“方法试验/待验证”及已知事实，不使用正式五状态标签。通过工程门槛但样本信息不足时，可以正式发布“还说不准”；报告仍收录，但不参加数字排名。安装阻塞记录收录，显示“没法测”，不参加数字排名。

### 2.6 两个边界（防五状态误用）

1. **安装失败双重记录**："能力结论：🚧没法测（原因：安装失败）"+ "安装环节：❌失败"分开记。插件的安装初始化本身是交付能力的一部分，安装失败不能被中性标签掩盖。
2. **实验无效 ≠ 证据不足**：实验无效是运行层状态（判分器故障、环境崩），处置=作废+留痕+重跑；证据不足是有效实验的信息不够。禁止把"实验无效"悄悄转成"证据不足"——前者是过程不可信，后者是信息不充分。

**种子与条件的等价性**：同种子 ≠ 同条件（服务端可换实现）。服务端不支持种子时，用替代方案（固定调用窗口 + 多次重复估波动），并如实标注。

## 3. 任务契约与状态管理

### 3.1 每个任务正式执行前必须有任务契约

1. 初始环境与输入（冻结数据优先）
2. 预期最终状态
3. 必须满足的验收条件
4. **明确禁止的副作用**
5. 可接受的部分完成状态
6. 超时、依赖故障、执行中断的处理
7. 判分器版本及其已知局限

**验收器提醒**：DOM 在 ≠ 功能对；哈希同 ≠ 内容符合要求；副作用核对要先定义"允许哪些"。
**盲评要求**：人工评审前去掉插件名称、独有界面和品牌线索；无法去掉就登记“非盲评”，不能把它当盲评证据。规定必须盲评的人工部分须重新遮蔽并评分；机器验收结果不因这一点自动作废。
**外部依赖**：网页/API 优先冻结数据/录制响应/受控测试服务；确实冻结不了，报告披露可变性。

### 3.2 状态快照三档制

| 档位 | 处理方式 |
|------|---------|
| 可完全重置 | 恢复到基线快照 + **验证关键状态确实恢复** |
| 只能部分重置 | 列明不可重置项，用独立账户/命名空间/隔离资源 |
| 无法可靠重置 | **不得声称完成了严格同状态对照**——改用可接受的替代设计，或该项实验标"无法满足要求" |


**每类正式任务的四要素（缺一则不得纳入严格配对）**：

1. 必须恢复的状态对象清单
2. 验证恢复成功的独立检查（不许用被测插件自身的状态报告做验证）
3. 不可恢复的外部状态（发出去的邮件、已提交的表单——用沙箱/模拟服务挡住）
4. 恢复验证失败的运行处置：**该次运行不得计入配对样本，留痕**

**快照契约**：快照包含哪些对象、如何验证恢复成功、哪些外部状态不在覆盖范围——三者写死，否则"初始状态快照 ID"只是看似完整的死字段。

有外部副作用的任务（发邮件、提交表单、删文件）：优先沙箱 + 模拟服务 + 测试账户 + 虚拟数据。

## 4. 安全：六威胁 + 一票否决的完整生命周期

**六类威胁**：提示注入 / 权限越界 / 数据外传 / 破坏性操作 / 凭据保护 / 供应链与更新行为漂移。

**三分法禁用混用**：未测（没考）≠ 未发现问题（考了没抓到）≠ 已验证通过（考了有通过证据）。


### 4.1.1 安全事件确认门槛（按严重度分级，写死）

| 严重度 | 例子 | 确认所需证据 | 是否需复现 |
|--------|------|------------|-----------|
| 🔴 关键 | 未授权外传、不可逆破坏 | 原始事件记录 + 目标资源状态 / 权限上下文（至少一项独立佐证） | **不需要**——复现本身可能造成新损害，单次充分证据即可确认 |
| 🟠 高 | 越权读写、凭据入日志 | 事件记录 + 可重复验证，或两名审查者独立复核结论一致 | 是，或双人复核 |
| 🟡 中 | 该确认未确认、降级未报告 | 可重复验证 | 是 |

**可疑关键事件的处置**：先停止危险测试，临时暂停推荐并标“调查中”，保全证据，通知作者。14 天内公开进展和依据：确认事件、解除临时暂停，或说明仍需调查及下一次更新时间。证据充分可单次确认，不因未复现而忽略；证据不足不写成已证实事实，作者不回应也不自动等于事件成立。

### 一票否决的精确语义

| 问题 | 规则 |
|------|------|
| 否决什么 | 当前版本的**推荐资格**（不是插件本身，不是历史记录） |
| 何时生效 | 证据足够确认后；调查期间标"**调查中**"，未确认前不当最终事实 |
| 何时解除 | 修复后**重测受影响的风险路径 + 回归测试**通过 → 新版本重获资格 |
| 什么不能解除 | 旧版本历史失败记录永久保留，新版本报告里并列展示 |

**防两个极端**：不能反复重试把严重事件"试没了"（同一风险路径重测次数预注册封顶）；也不能一次无法复现的异常就永久封杀（标"单次观察"，进复测队列）。

**风险等级判定规则**（替代按功能贴标签）：

```
风险等级 = f(基础类别, 实际授予权限, 潜在影响范围, 已有缓解措施)
```

只读插件读到敏感文件照样高危；执行代码在沙箱里可能中低危。**每项判定要给出可复核的映射依据。**

## 5. 成本口径

**两个核心指标**（同难度同验收标准才可比）：

- **总单位成功成本** = 全部成本 ÷ 成功任务数（答"用这个插件干活贵不贵"）
- **增量单位成功成本** = (插件总成本 − 基线总成本) ÷ 插件多带来的成功数（答"装它比不装它值不值"）

**分母规矩**：
- 成功数 = 0 时显示“**不适用：没有成功任务**”，同时展示实际总花费，禁止除零
- 增量成功数 ≤0 时，增量单位成功成本显示“不适用：没有多干成任务”；分别报告成本差和成功数差，不能用负比值暗示划算
- "总成本"含什么要写清：订阅费/固定部署费/人工操作费是否计入，逐项列
- 失败任务成本计入；缓存条件（冷/热）标注；机器等待 ≠ 人工操作，分开计时
- 观测不到标"估算值 + 误差来源"，禁止填 0

## 6. 快测的定位（统一准入边界）

**"官方测评"是上位概念，下分三档**：

| 档位 | 测什么 | 能用什么标签 | 排名资格 | 评论权限 |
|------|--------|-------------|---------|---------|
| 体验快测 | 安装、功能点、卸载残留 | “快测记录：查到哪些、结果怎样” | 不进能力榜 | 可解锁（标注基于快测） |
| 标准测评 | 完整对照实验 + 统计判定 | 五种结论状态 | 满足域门槛后进能力榜 | 可解锁 |
| 深度审计 | 标准 + 安全六威胁全项 | 五种结论 + 指定范围安全结论 | 满足域门槛后进榜 + 指定场景依据 | 可解锁 |

规矩：快测**禁用"通过""合格"这类词**，只描述检查结果（"安装成功，5 个功能点 4 个可用"）；快测失败不影响后续标准测评排期。

## 7. 测评系统自检（量化门槛）

每项自检建立三字段：**测试样本 / 通过阈值 / 失败处置**。

| 项目 | 样本 | 通过阈值 | 失败处置 |
|------|------|---------|---------|
| 判分器正确性 | 已知对/已知错/边界样本集（每类 ≥20） | 回归全对 | **停用该判分器版本**，重算受影响历史报告 |
| 稳定性 | 同环境重复 10 次 | 波动在预注册范围内 | 暂停发布，查环境 |
| 检错能力 | 注入 ≥3 个已知缺陷版本 | 全部抓到 | 题库/验收器返工 |
| 特异度 | 无能力变更版本 | 无误报"提升" | 查判分器 |
| 评分一致性 | 抽样 ≥10% 双人盲评 | 分歧率 < 预注册值 | 修订评分规则，重评该批 |
| 外部复现 | 每季度 ≥1 人重跑公开协议 | 差异在容许波动内 | 记录原因：协议/环境/插件变化 |

**变更触发**：判分器、协议、关键依赖发生重大变化 → 立即跑相关回归，不等季度。

## 8. 隐私与证据治理

**最小化原则**：测试优先合成数据 + 测试账户；公开报告只留必要脱敏证据。

**审计元数据与敏感载荷分离**：
- 只追加、不可变的是：审计元数据（哈希、时间戳、run 关联、访问记录）
- 敏感载荷（原始录像、对话日志、令牌）单独受控存储，**有保存期限和删除通道**——"只追加不覆盖"绝不能让敏感数据永远无法删除

**访问控制**：未脱敏证据限定角色访问，访问留痕。

## 9. 题库生命周期

题库规范按“草稿 → 公示征求意见（至少 7 天）→ 验证 → 正式冻结 → 使用 → 退役”管理。公示任务类型、分布、判分和局限，不公示当前保密实例及答案键；公开题可逐题征求意见，保密题由受控独立人员校验。否则不能一边公开完整题目，一边称它保密。

- 公开题用途：方法透明、外部复现、缺陷反馈
- 保密题用途：防过拟合、测未见任务；产生/保管/轮换/退役留痕；泄露 → 启动调查 + 相关历史成绩重估
- 公示期防过拟合：公示 ≠ 冻结后可直接上榜；新域进榜前还须验证题目能区分已知对错行为
- 新模型版本出现 → 评估污染风险（蜂巢留出材料机制）

## 13. 基线、证据与发布的完整约定

本节是发布前必须填写和检查的执行约定。文档写了规则，不代表题库、代码和环境已经通过验证；每次实验都要绑定实际文件哈希和验证记录。

### 13.1 装与不装到底差什么

- B0：关闭被测插件及无关插件，保留两组相同的宿主默认功能。
- P：相同宿主、模型、历史注入、题目和预算制度，启用被测插件。
- Δ = P 分数 − B0 分数。报告同时展示两边的绝对分。
- 同历史注入不等于每次问答都提供完整历史。跨会话时，B0 使用宿主正常能保留的信息，P 可以使用插件的记忆；这是接入收益的一部分，不等于证明内部机制优于所有替代方案。
- B1 简单信息基线是横评可选项：固定规则注入摘要/相关材料，登记预算；未执行不能假称已控制。
- 插件额外调用模型、外部 API 或更多 tokens：披露资源增量；不能称为同资源下模型本体变强。
- 安装、启动和重试预算预先登记；故障后不能只补跑差的一边。插件自身失败按任务契约计分；确认的实验环境故障整对作废，理由和补跑关系保留。
- 有效重跑数固定，不等于容许无限补跑：每个配对预先设外部故障补跑上限。达到上限仍不完整，停止该批并记录阻塞，不跳过难场景、换成容易场景或偷偷缩小分母。
- 原因不明的崩溃先隔离调查，不能直接算“环境问题”删除。插件引发宿主崩溃属于被测系统表现；只有独立证据支持外部实验故障才可整对作废。
- 安全中止优先于样本计划。不得为了跑满数量继续危险操作；报告保留中止原因和安全处置，能力分析按有效性与样本门槛处理。

### 13.2 题集与权重没有隐形默认值

“考卷 B”“轨 B”“89 卡”仅是来源别名。正式任务包必须有源文件/仓库位置、提交或包哈希、授权条件、题目和答案键数量、场景分组、权重、污染风险和适用边界。拿不到材料只能标待核实，不得据此声称首域可上线。

记忆域来源正确性和事实支持率分开报告；摘要无需逐字复制原文，但引用须定位到能支持答案的记录。写入诊断区分“没写入新值”和“写了却读出旧值”。遗忘分为不再召回、逻辑删除、物理删除、备份残留，不用一个绿勾表示全部。

保密题在实验前登记题包和答案键哈希，由受控角色管理，执行者仅在运行阶段取用。退役后延迟公开；未公开的当前题须接受受控外部审计，明确公众暂时不能逐题重跑的限制。

### 13.3 最小证据和数据模型

每个实验批次包括：`experiment_id`、`analysis_id`、协议/手册哈希、任务包和判分器哈希、环境 ID、插件身份、样本计划、场景分组、顺序种子、预算、阈值、停止规则、披露关系。每个运行包括：`run_id`、`pair_id`、场景 ID、条件、时间、原始输入、输出、产物、工具事件、快照验证、费用及有效性理由。

报告由有效运行和判分输出生成；人工叙述允许编辑，分数、区间和标签禁止手改。复核人、结论证据列表、报告哈希、更正关系和失效状态必须可查。

证据目录建议：

```text
{experiment_id}/
  manifest.json
  protocol.json
  taskset-manifest.json
  environment.json
  pairs.jsonl
  runs/{run_id}/
    inputs.json
    events.jsonl
    artifact-manifest.json
    snapshot-check.json
    costs.json
    validity.json
  analysis/{analysis_id}/
    analysis-manifest.json
    scores.json
    result.json
  review.json
  public-redacted/
```

最小证明集：正确性需输入、实际产物和验收结果；成本需计量或估算来源；安全需事件、权限上下文和独立佐证；状态恢复需清单和独立检查。缺任一必要证据就不能重算相应结论。

### 13.4 失效必须传到网站

- 文件缺失、哈希不符、判分器撤销：计算器拒绝生成受影响结论，并返回机器可读错误及缺失对象。
- 建立判分器/证据 → run → analysis → report → 榜单/badge 的依赖关系。
- 旧报告仍保留历史文本，但醒目标注“证据不完整/待复核”；从有效榜单移出，相应 badge 失效。不可让旧缓存继续当有效成绩。
- 分数重算不覆盖原记录：保留旧输出、撤销原因、新报告和复核结果。
- 重算结果比较时规范化分数、区间和标签；时间戳、审计人员等元数据允许不同，不能因此误判计算不一致。

### 13.5 安全、权限和证据保留

实验使用合成敏感材料和测试密钥；插件视为不可信。隔离机不得挂载个人或生产目录；设置文件、网络、进程、费用及超时边界。网站生产机与插件执行环境分离。未知上传行为标“未验证”，不是“无风险”。

原始敏感载荷默认保存 90 天，另有必要保存时须记录目的、授权和期限。删除前由复核者检查脱敏替代证据是否保留全部计分所需信息，登记原件/替代件哈希、转换规则和核验记录。只有足够支持重算和审计的替代件才能继续支持有效成绩；否则报告标“证据核验受限/待复核”，退出有效数字排名和推荐徽章，不以原件哈希冒充可验证证据。原件删除事实在页面说明。

审计记录和历史结论长期保留不等于保留真实秘密；审计元数据也须最小化，必要的个人信息删除或纠正以追加处置记录说明。哈希只能检查内容是否一致，不证明内容真实。

### 13.6 复核、修复和商业边界

执行与复核分离。原始 UI 无法遮掉品牌时记录为非盲评，不能称盲评；不必删除整次机器验收结果。需盲评的人工部分必须重新遮蔽并评分。

安全暂停与能力状态独立；关键事件单次充分证据可确认，证据尚不充分则调查。14 天内给出确认、解除或需要进一步调查的公开理由，不用超时自动洗白。

7 天是集中申诉窗口，不是拒绝纠正已证实错误的期限。免费复测按公开队列和产能安排，不承诺无限次或无限优先；修复后的新版本结果更新，旧版缺陷记录保留。

付费季度抽验以当季已交付加急报告为分母，记录抽样种子，抽取 `ceil(20% × N)` 份，N=0 则无需抽验；复测人不参与原执行。精选整合包、分成和推广明确利益关系，不改变能力排名和测试条件。

跨宿主仅适用于声明支持多宿主或可迁移 MCP 接口的插件；同模型不可用时标“跨配置观察”，DSH 专用插件标 N/A，不因不适用扣能力分。企业推荐绑定具体场景、部署、权限、数据类型和验证日期，不证明到处都安全。

### 13.7 排名、时效和风险等级

- 数字对比仅用于同域、同题集/权重、同模型、宿主及预算制度的可比组；两份报告的差值高低不自动证明两个插件彼此有明显差别。需要宣称 A 优于 B 时，预注册同场景的 A/B 直接配对比较，并处理多重比较。
- “还说不准”“没法测”、方法试验及证据失效记录仍可见，但不参加数字排名。明确负贡献正常收录，不因难看隐藏。安全暂停推荐的有效能力数据可以展示，但不进入“值得试”入口。
- 测评默认有效期为测评完成后 90 个自然日。临近到期进入复核队列；到期自动退出当前有效排名和推荐徽章，保留历史结论。仅改页面日期不能延长有效期，须有按变更范围执行的复核记录。
- 版本、权限、数据流、模型或宿主变化可提前触发相关标签待复核。旧报告不自动适用于新版本；远程服务无法锁定实现时注明观察窗口，检测到行为变化立即复核。
- 风险等级不得仅用 f(...) 就宣布已评估。每个场景规范须提供低/中/高/关键的判例、权限、影响范围、缓解有效性及判级理由，由独立复核者确认。无可执行映射或关键权限未查明时标“未评估”，不授予需要该等级的场景推荐。
- 风险等级描述潜在影响，安全事件描述已发生行为；不把“高风险但受控”与“已确认违规”混成一回事。

### 13.8 文档和缺失信息的优先级

完整网站方案是唯一方案正文；原简版仅作入口摘要。工程执行以本手册和正式域规范为准，验证计划引用它们。出现不一致先停止相关正式发布，登记冲突、修订和哈希，再补跑受影响验证，不能执行者临场挑更宽松的一条。

每个待填项目登记负责人、材料来源、验收证据和状态。题包、权重、统计实现、风险映射及复核人未齐是上线前任务，不代表文档已替它们完成验证。
