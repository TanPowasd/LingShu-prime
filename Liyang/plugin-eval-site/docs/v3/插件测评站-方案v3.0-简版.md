## 1. 我们干什么

插件很多，介绍很多，但用户最想知道的常常没人说清：装得上吗？真能干活吗？要不要一直盯着？多花钱值不值？会不会乱传资料？卸载干净吗？

**我们替用户装一遍、用一遍，再老实写报告。**

## 2. 结果只有五种说法

| 结论 | 什么意思 |
|---|---|
| ✅ **真有用** | 多跑几遍后，结果还是明显更好 |
| ❌ **帮倒忙** | 装了以后，结果明显变差 |
| ➖ **没啥差别** | 测得够多，也测得够稳，没看到值得在意的差别 |
| ❓ **还说不准** | 现在的结果不够，不能说有用，也不能说没用 |
| 🚧 **没法测** | 装不上、环境不支持，或任务不适合；具体原因写清 |

- “没啥差别”不是绝对一样。
- “还说不准”“没法测”和试验中的方法也会发出来，但不参加打分排名。
- 安装失败就写安装失败，不编分数凑数。
- 实验本身坏了（判分程序报错、测试服务断了）不算插件输，作废重跑并留痕；插件把宿主弄崩不算环境问题。
- **安全提醒单独显示**：可以“干活真有用”，同时因为乱传资料“暂停推荐”。

## 3. 三张单分开摆，不给总分

**能力** / **好不好用** / **花费与安全**，各看各的。第三张里钱和安全也分栏。

四个标签分开标：

| 标签 | 选项 |
|---|---|
| 面向谁用 | 个人 / 团队 / 企业 |
| 我们测到哪 | 作者自测 / 快测 / 标准 / 深度审计 |
| 风险多大 | 低 / 中 / 高 / 关键 / 未评估 |
| 现在推不推 | 可推荐 / 限定场景 / 待复核 / 暂停推荐 |

“完成测评”不等于“成绩好”，更不等于推荐。

## 4. 钱怎么算

- **每干成一件花多少钱** = 全部花费 ÷ 干成数。
- **多干成一件多花多少钱** = 比不装多花的钱 ÷ 多干成的数。
- 一件没干成、或多干成为零，写“不适用”，仍展示实际花费。
- 测不到的不能填 0：有依据写估算，没有就写“没测到”。

## 5. 我们怎么保证不是碰巧

> 同一套任务，装和不装都跑；换顺序、多跑几遍，每次从干净状态开始，再看差别站不站得住。

- 不能只重跑差的一边。
- 不能边看成绩边决定“这次很好，停了”。
- 不能因为跑了三次就自动说靠谱。
- 环境、题目、模型或预算不一样，不放在一起比。
- 分数默认只管 90 天，到期退出推荐和排名；改日期不算续期。

## 6. 我们不做的事

不说“提升了 AGI 能力”；不说“大家都该装”“到处都安全”；不用星级；不搞全能总榜；不拿星数和热度当能力；不因作者付钱少测、改分或藏差评。

## 7. 现在到哪一步了

**目前只有方案和验证计划，还没有经过验证的正式成绩。**

正式能力榜要同时满足三件事：端到端验证通过、首个能力域的任务和统计规范正式冻结、上线验收清单通过。**不是日子到了就开榜。**

在那之前，网站可以先发体验快测和标清范围的方法试验。
