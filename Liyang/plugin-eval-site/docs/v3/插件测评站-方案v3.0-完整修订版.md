## 1. 我们要解决什么问题

插件很多，介绍也很多，但用户最想知道的往往没人说清：

- 装得上吗？是不是一装就报错？
- 真能帮我干活，还是只会说“已经完成”？
- 要不要一直教它、盯着它？
- 多花多少钱，值不值？
- 会不会乱删文件、乱传资料？
- 不想用了，能不能卸干净？

**我们替用户装一遍、用一遍，再老实写报告。**

不写未经核实的“插件已有一万多个”，不把“没人测过”说成事实。生态规模要写清来源、清点日期和怎么算；没查清就不写数字。

## 2. 谁会来看

- 学生：学习、整理资料、写作。
- 办公人群：写东西、整表格、批处理文件。
- 非程序员：做小网页、小工具，别让我碰代码。
- 开发者：写代码、查资料、跑自动化。

大家都想：**帮我干活，别让我重复交代，别花冤枉钱，别出事。**

作者和研究人员也能看细节、下载数据、提出错误，但首页不是写给专家的。

## 3. 我们不做什么

- 不说“提升了 AGI 能力”。
- 不说“大家都该装”“到处都安全”。
- 不用星级，不搞全能总榜。
- 不拿星数、广告、评论热度当能力。
- 不把“没查到问题”说成“绝对没问题”。
- 不因作者付钱就少测、改分或藏差评。

我们说的每个好坏，都有范围：**哪个版本、什么环境、做了什么任务。**

## 4. 插件分三类，不能拿一把尺子硬量

| 类别 | 是什么 | 怎么测 | 能不能进能力榜 |
|---|---|---|---|
| 能力型 | 让 AI 记得住、找得准、少混淆 | 装和不装，考同一套题 | 完成标准测评，并达到该域门槛后可以 |
| 工具型 | 让 AI 能操作浏览器、文件、终端 | 做真任务，检查真的做成没有 | 完成标准测评，并达到该域门槛后可以 |
| 体验型 | 界面更顺手、信息更好看 | 安装、使用、卸载快测 | 不进能力榜 |

同一个插件可以有不同部分，分别测。纯提示词包装先放作者介绍；证明有实际架构增量且有合适题目，才能申请正式能力测评。无法独立运行的项目记录阻塞原因，不装作测完了。

### 4.1 工具型四件事分开看

1. **干对没有**：看文件、页面、数据库和测试结果，不听“我做完了”。
2. **有没有乱来**：越权、外传、乱删、该停不停。
3. **花得多不多**：钱、时间、额外操作。
4. **出错能不能接着干**：任务恢复、重复操作、状态丢失。

能力判定主要看干对没有。安全问题影响当前版本能不能推荐；花费和恢复情况单独摆，不互相抵分。

## 5. 结果只有五种说法

| 页面结论 | 白话解释 |
|---|---|
| ✅ **真有用** | 多跑几遍后，结果还是明显更好 |
| ❌ **帮倒忙** | 装了以后，结果明显变差 |
| ➖ **没啥差别** | 测得够多，也测得够稳，没看到值得在意的差别 |
| ❓ **还说不准** | 现在的结果不够，不能说有用，也不能说没用 |
| 🚧 **没法测** | 装不上、环境不支持，或任务不适合；具体原因写清 |

“没啥差别”不是绝对一样，是没看到值得在意的差别。“还说不准”不只是少跑几次：有时结果就在边上，再测也未必能马上下结论。

“还说不准”“没法测”和还在试验的方法，也会老实发出来，但不参加打分排名。装不上就写装不上，不编一个分数凑数。

查明确实是实验本身坏了，比如判分程序报错、测试服务断了，不算插件输，也不悄悄删掉：标“这次作废，原因……”，保留记录再重跑。插件自己把宿主弄崩，不能冒充环境问题；原因还没查清，先写“正在查”，不删差结果。安装失败则同时写“安装失败”和“能力没法测”。

**安全提醒单独显示。** 一个插件可以“干活真有用”，但因为乱传资料“暂停推荐”。能力结果不能被偷偷改成零分或抹掉。

## 6. 怎么知道不是碰巧

页面用一句话讲明白：

> 我们用同一套任务，装和不装都跑；换顺序、多跑几遍，每次从干净状态开始，再看差别站不站得住。

后台要求：同题对照、顺序随机、状态独立恢复、配对重跑、固定样本量、报区间、门槛提前写好。详见手册。

- 不能只重跑差的一边。
- 不能边看成绩边决定“这次很好，停了”。
- 不能把同一个故事的很多问题当成很多独立故事。
- 不能因为跑了三次就自动说靠谱。
- 环境、题目、模型或预算不一样，不直接排在一起比。

首月主读数是装与不装的差值。复杂表格可叫 Δ，首页就写“比不装多了多少”。插件多用了模型或钱，必须说清，不说成模型本身变聪明。

## 7. 能力域和先后顺序

| 能力域 | 用户关心什么 | 测法 | 启动状态 | 顺序 |
|---|---|---|---|---|
| 记忆 | 别让我重复交代 | 同题对照、跨会话、更新和回源 | 蜂巢材料是候选，版本和题包待核实 | 首月首个正式域，达门槛再开榜 |
| 因果理解 | 改了需求，还能不能想明白 | 看该变的是否变、不该变的是否保持 | 候选材料待核实 | 首月方法试验 |
| 工具使用 | 抓数据、整文件、跑脚本 | 实际产物验收 | 待建任务契约 | 第二顺位 |
| 安全边界 | 别被暗指令带偏 | 受控攻击和权限检查 | 待建专项；基本安全检查从第一天做 | 第二顺位，并行 |
| 世界模型/产物一致性 | 页面真能跑、图和字对得上 | 功能与产物验收 | 定义待公示，不与普通网页任务混为一谈 | 第三顺位 |
| 协作 | 大任务分工后能做成 | 同预算、共享状态、故障恢复 | 待建 | 第四顺位 |
| 感知 | 看懂截图、表格 | 答案和定位核对 | 待建 | 按需求排 |
| 推理规划、表达与人格 | 多步骤不走丢，人设不乱 | 分项任务 | 待建 | 远期 |

扩域要公示至少 7 天、题目能区分已知对错、判分程序过回归、保密题受控、跑通真实插件并有外部复核。跑通一个插件不代表整个域已经有效；门槛没过，继续写“试验”。

各域独立，不合成全能榜。参考认知理论可以在方法页写清来源，不能借学术名头把工程题库说成 AGI 认证。

## 8. 我们到底测了多深

| 档位 | 做什么 | 可以怎么说 | 排名 |
|---|---|---|---|
| 体验快测 | 安装、指定功能、卸载和基础权限观察 | “安装成功，5 个功能点 4 个可用；还有这些没查” | 不进能力榜 |
| 标准测评 | 完整任务、装与不装对照、统计、复核 | 五种能力结果 | 满足域门槛后可进榜 |
| 深度审计 | 标准测评加六类安全专项、部署与治理检查 | 能力结果 + 指定范围安全检查 | 满足域门槛后可进榜，不能说到处安全 |

体验快测不测能力 Δ，不用“认证通过”“合格”。需要对照的短测只能叫“能力试跑”，标“观察结果，不进榜”。快测可以失败，也照样发布；失败不阻止后续申请标准测评。

首月不承诺每天测很多个。先跑出真实人时和成本，才定每周数量。

## 9. 四个标签分开看

| 标签 | 选项 | 白话解释 |
|---|---|---|
| 面向谁用 | 个人 / 团队 / 企业 | 作者想给谁用，不代表已经验证 |
| 我们测到哪 | 作者自测 / 快测 / 标准 / 深度审计 | 自测只是声明，不是官方成绩 |
| 风险多大 | 低 / 中 / 高 / 关键 / 未评估 | 看权限、资料、影响和防护，不按名字猜 |
| 现在推不推 | 可推荐 / 限定场景 / 待复核 / 暂停推荐 | 绑定版本、环境和日期 |

三张单分别摆：能力、好不好用、花费与安全。第三张里钱和安全也分栏，绝不算一个总分。

### 9.1 场景推荐

- **个人日用**：指定快测项目都有记录，权限小，安装和卸载符合预先写好的要求；只推荐已查的功能，不替未查部分背书。
- **小团队**：完成标准测评，指定团队任务和共享数据要求满足，没有已确认的严重安全问题，风险符合场景要求。
- **企业生产**：深度审计，指定部署、数据类型、权限和风险专项有证据；作者有可用回应渠道。

“完成测评”不等于“成绩好”，更不等于推荐。具体门槛先写在任务/场景规范里；没写或没测，就不能发标签。“没啥差别”也可能因为更省钱、更好用适合某些人，必须把理由说清。

## 10. 钱和时间怎么写

每篇都写：一共花了多少、干成多少、失败花了多少、需要人动手多久。

- **每干成一件花多少钱**：全部花费 ÷ 干成数。
- **多干成一件多花多少钱**：比不装多花的钱 ÷ 多干成的数。
- 一件没干成，写“不适用：没有成功任务”，仍展示实际花费。
- 没比基线多干成，写“不适用：没有多干成任务”，单列花费差和结果差。
- 测不到的不能填 0：有依据写估算和误差来源，没有依据写“没测到”。
- 固定部署费、订阅费、人工费算不算，逐项说明；等待时间和手动操作分开。

不能用不同难度任务算出的单价直接比较。后台模型调用和外部服务费都计入。

## 11. 安全出事怎么处理

检查六件事：暗指令、越权、外传、乱删乱改、凭据保护、更新后行为变化。

- 已确认严重问题：暂停当前版本推荐，能力成绩和历史记录保留。
- 可疑但证据不够：写“调查中”，先提醒风险，不当成已证实事实。
- 修好后：复测受影响路径并做回归，新版本可以重新推荐。
- 单次充分证据可确认严重事件，不为了复现再造成一次损害。
- 没测、没发现、通过指定检查，必须分开说。

测评用测试账户、假资料、限额密钥和隔离环境。不会拿用户真实秘密来试。公开录像先遮掉隐私，原件受控保存；保存和删除规则见手册。

## 12. 作者还管不管

保留“装死”的口语说法，但一定写明依据：**已通知的已知问题超过 90 天没回应**，不是“几个月没更新”。

看三件事：问题修没修、回应花多久、宿主升级后还能不能用。

- 只影响维护提示和场景推荐，不加减能力分。
- 稳定不发版不扣分，频繁发版也不自动加分。
- 变更按内容触发重测，不只看版本号大小。
- 修 bug 可免费申请复测，公开排期；产能不够就写预计时间。
- 修复后的新报告更新，旧版本踩过的坑不删。

## 13. 评论、曝光和找错

- 网友体验放单独栏目，不混进官方成绩。
- 完成官方快测或标准测评的插件可开评论区；标清基于哪一档，失败也算已测。
- 评论尽量写版本、环境、任务、结果和证据，支持作者回复。
- 热度只影响先测谁，不决定谁更好；新插件保留基础曝光位。
- 作者自测放“作者声明”，不冒充官方成绩。
- 指控先当线索，有证据再下结论；证实真问题就公开更正，不搞人身攻击。

## 14. 公信力三条铁规矩

1. **自家人管得更严**：灵枢系强制披露关系，站外独立复核；没有独立复核就标内部试验，不假装第三方认证。
2. **花钱只能插队**：差评照发，页面挂标，免费和付费测法一样；当季加急报告抽 20% 换人复测。
3. **测错了就认**：7 天集中申诉，之后发现可证实的错照样改；新版写明原因，不删旧文。

钱买不到能力成绩和推荐标签。作者可以指出事实、算法、任务和执行错误，不能因不喜欢结果要求撤稿。

## 15. 测评站自己也要被测

每季度，以及算法、题目、关键环境变更后检查：

- 正确、错误、边界样本会不会判错；
- 同环境重复会不会乱跳；
- 已知坏版本能不能抓到；
- 没变化会不会误报进步；
- 两个人盲评会不会差很多；
- 外人能不能按说明重算。

有错停用相应版本，查受影响的历史报告；旧页面、榜单和徽章也要标失效，不只是新程序报错。

验证结果只能说明已经查过的范围，不证明能抓到所有未知错误。具体样本、门槛和处置见手册。

## 16. 网站有哪些页面

### 首页

先给用户四个入口：**我想干什么 / 哪些值得试 / 哪些有坑 / 怎么测的**。

展示最新报告、已测/未测状态、能力覆盖和公开排期，不用一个“总分”充门面。

### 插件页

告诉用户：它能干什么，适合谁，装起来麻烦吗，多少钱，有什么坑；附版本、测评深度、推荐范围、作者回应、更新记录和报告。

### 报告页

先讲人话，再把证据放出来：

```text
结论：真有用 / 帮倒忙 / 没啥差别 / 还说不准 / 没法测
适合谁：……
不适合谁：……
这次做了什么：……
装与不装差多少：……
花了多少钱、多久：……
最需要注意的坑：……
我们查了哪些，没查哪些：……
哪个版本、哪天测的：……
利益关系和复核：……
想看细节：任务、运行记录、算法、证据、更正
```

标准报告包含两边绝对分、差值、区间、独立场景数和重跑数。区间旁写白话：“按这批任务估，差别大概在这个范围；范围很宽，就先别下定论。这不是保证下次一定落在里面，也不代表所有任务。”

### 其他页面

- 场景选插件：个人、团队、指定企业场景。
- 分域榜：只有同模型、宿主、题集和预算制度的结果才放在一起比。两份报告差得多，不等于这两个插件互相之间就一定有明显差别；要说 A 比 B 好，得把两个插件放进同一批任务直接比。
- 有效期：成绩默认只管 90 天，到期就退出当前推荐和排名，历史结论留着。改个日期不算续期。
- 风险等级：按权限、影响范围和防护措施逐项给理由，不能靠功能名字猜。没查清就写“未评估”，不硬给一个等级。
- 怎么测：方法、题目、判分程序和局限。
- 排期：免费/加急、当前状态、阻塞原因。
- 找错和更正：提交入口、处理结果、新旧版本。
- 月度账本：测了多少、花了多少、失败多少。

未测就写“未测”，不留空让用户猜。网页支持手机、易读字号、短句和清楚的按钮。

## 17. 怎么把网站做出来

先用 Markdown 内容 + 静态网站 + 版本化 JSON 数据，不急着做大后台。

- 报告正文可以人工写；成绩、区间、标签从有效证据自动生成，不能手填。
- 发布前检查必要字段、公式、证据链接、隐私和复核。
- 实验环境和网站服务器分开，不在网站机器上运行不可信插件。
- 后续评论和排期增加账户、权限、审核、防滥用和备份。
- 保留数据出口，给灵枢 intake 使用；成绩是参考输入，不是唯一真源。

建议页面路径：首页、插件页、报告页、各域榜、方法页、排期页、更正页、账本页。具体字段和证据目录见手册。

### 17.1 运行到发布的顺序

```text
登记选品和关系
→ 写好任务、预算和门槛
→ 安装与状态清点
→ 装/不装配对执行
→ 保存证据与实际结果
→ 自动判分
→ 独立复核
→ 发布
→ 接收申诉与版本变化
→ 需要时失效、重算、更正
```

## 18. 钱从哪来，谁来做

M1 免费排期。M2 管线稳定后再尝试付费加急、打赏导流和精选整合包，全部披露关系。

加急不缩短测试、降低标准或霸占免费队列；接不下就不接。badge 只写具体版本、域、日期和状态，过期或撤销就失效，不能叫“AGI 认证”。

最少需要：

- 执行者：装、跑、记证据、写初稿。
- 独立复核者：查证据和算分，不给自己签字。
- 方法/工程负责人：题目、算法、程序和变更。
- 网站维护：发布、权限、备份、评论。

小团队可以兼任不冲突职责，但执行与独立复核分开。人员不足就降产量，不降标准。

## 19. 第一个月干什么

| 周 | 目标 |
|---|---|
| 第一周 | 核实材料和插件；手册及任务规范公示 7 天；建立环境、快照和回归；少量体验快测；原型链路跑通 |
| 第二周 | 真实链路 + 受控夹具 + 三类故障注入 + 独立重算；尝试第一篇记忆报告，门槛未过就标方法试验 |
| 第三周 | 网站上线体验内容和方法试验；完成验证后发布正式报告；评论与排期上线；按实际产能安排快测 |
| 第四周 | 16 项验收汇总、首月账目、未完成项；决定记忆榜开不开；工具域先写 10 个候选任务契约，验证后再冻结 |

验证失败，正式报告和能力榜顺延，网站仍可发布标清范围的体验检查。不是日子到了就必须开榜。

首月成功标准：真实链路至少完整跑一次；结果能独立重算；正面和负面结论都有证据；账目公开。正式能力榜还须满足端到端验证、域规范冻结和手册 16 项验收。

## 20. 怎么知道站点做得好不好

- 用户有没有找到合适插件：报告到仓库的点击只是参考，不当成实际收益。
- 别人能不能重算、重跑出相近结果。
- 复核发现什么错、改得快不快。
- 单篇花多少人时和钱，排期是否堵住。
- 测了哪些场景，还有哪些空白。
- 同一配置下成绩怎么变；不同模型和题集不拼成“生态越来越聪明”的曲线。

第一月先公开原始数字，不急着许愿增长目标。下一月产能按真实成本定。

## 21. 本次修订记录

**第一轮**

- 前台统一为五种白话结果，后台保留对应统计状态。
- “快测通过”改为具体检查记录，个人推荐只限已查范围。
- 安全暂停推荐不改能力成绩，企业场景不等于到处安全。
- 维护提示不加减能力分，稳定不发版不惩罚。
- 删掉未经核实的生态数量和现成题库承诺。
- 正式发布绑定文件哈希，正式榜须有工程证据，不按日期强行上线。
- 配对统计、独立场景、固定样本、成本分母、失效传播和行为夹具的修订见配套手册与验证计划。

**第二轮**

- 配对成功率的算法要按配对结构明确实现，不能套单组区间。
- 五种结果先满足精度门槛再判；算法没校验好、证据不全，先标“待验证”，不给正式标签。
- 标准测评和深度审计只有达到能力域发布门槛，才进正式榜。
- 原因不明的崩溃先查清，不直接当环境问题删掉；补跑有上限，不跳难题、不偷偷缩小分母。
- 安全事件 14 天内公开进展，不用超时自动洗白。
- 报告默认 90 天有效；到期退出推荐和排名。
- 排名只在同一可比组内做；要比较两个插件，必须直接放在同一批任务里比。
- 风险等级逐项给理由，查不清写“未评估”。
- 原件删除后，只有脱敏替代证据仍够用，成绩才继续有效。
- 本文为唯一完整方案；原简版改为面向用户的一页摘要。
