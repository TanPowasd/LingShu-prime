> 作者：pes-v3-protocol · 2026-10-10（CST）· 基线提交 `aec456d`（docs/v3 登记哈希，`sha256sum -c SHA256SUMS` 4/4 OK）。
> 对照对象：`SPEC_接线规范_v0.1.md`、`SPEC_v0.2_修改提案_统计口径.md`、`harness/`（classify/compare/compareA/run/sandbox/recorder/judge/ledger）、`reports/`（两卷报告草稿、稳健性复核、站外复核包）、`LEDGER.md`、`OVERNIGHT.md`。
> 状态四档：**已满足** / **部分** / **缺失** / **冲突**（v2.2 与 v3 规则相反，或 v3 文档之间不一致）。
> 本文只列差距；v3 文档之间的冲突按验证计划"先列出、不擅自裁决"（§6）。本轮已新建的东西在"本轮补"一列注明。

## 0. 要点（先看这个）

1. **统计判定口径整体被替换**：v0.1 的四结论（✅/❌/😐/🚧）+"按题 bootstrap、种子 7、≥3 题、种子方向一致"与 v3 的五状态 + 运行层/发布层状态 +"按独立场景聚类、种子＝analysis_id 哈希、±5 分、半宽 ≤5、场景 ≥8"在多处**冲突**。本轮已实现 `harness/verdict_v3.py`（+独立参考实现、76 项回归），旧 `classify.py` 保留不动。
2. **独立单位是最大的硬缺口**：考卷 B＝一位使用者的一份历史，考卷 A＝一部小说，各只有 **1 个独立场景**。按 v3 两卷都只能出"方法试验"；已有五组对比重判后观察值全部 ❓（`reports/v3_重判_方法试验.md`）。要出正式标签必须先找到 ≥8 个独立场景的授权题包——这是**材料问题，不是代码问题**。
3. **"种子"不是"配对重跑"**：旧运行插件写入与召回每臂只做一次（三种子共用 `q/*.recall.json`），只重采生成器；没有每次从快照恢复、独立检查（手册 §3.2）。
4. **证据数据模型缺失**：没有 `experiment_id / analysis_id / pair_id / 环境配置 ID / pairs.jsonl / snapshot-check / validity.json`；`run_id` 就是输出目录名（续跑复用，不唯一）。
5. **安全通道、失效传播、90 天时效、四标签、成本分母规矩**在 v2.2 里基本没有；本轮补了算法层（`labels_v3.py`、`cost_v3.py`），但没有接到报告生成和网站。
6. **v3 文档之间有 9 处需登记的不一致/欠规定**（§9），其中两处直接影响实现（"数据检查失败"该归实验无效还是待验证；记忆域主要指标的候选题源本身无法满足独立场景要求）。
