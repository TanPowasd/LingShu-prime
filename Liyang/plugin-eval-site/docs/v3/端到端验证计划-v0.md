# 端到端验证计划 v0（修订版）

> 只回答一个问题：**这套测评系统，能不能把不可信的结论挡住？**
>
> 配套：[完整方案](<插件测评站-方案v3.0-完整修订版.md>)（r2）+ [工程协议手册](<工程协议手册-v1.1.md>)（r2）。三份文档及测试材料都登记哈希；文档冲突时先停止相关正式发布，再修订补跑。
>
> 标准有错就公开勘误，实现有错就修代码。不能为了通过测试降低门槛；也不能因为“已经冻结”就保留已知错误。

---

## 1. 验证对象与边界

**一个真实插件 × 记忆域 × 完整链路，另加受控测试夹具。**

候选：AskTheWay/dsh-auto-memory。候选名不代表已核实版本、星数或当前功能；执行前清点仓库/发布包、依赖、权限和实际状态。

任务来源候选：蜂巢真实历史轨或其他已授权题包。先取得题包、答案键、判分器、授权和版本，检查泄漏与场景分组；拿不到就标“材料待核实”，不能声称任务现成可用，也不能先写题目数量。

不能因为用了 MEMORY.md，就假定只需恢复一个文件。完整状态清单包括宿主历史、索引、缓存、数据库、配置、后台进程和外部服务状态。先检查实际实现，再选择快照档位。

只有一份相关历史时，本验证能证明管线处理这份材料的行为，不能证明跨场景能力；可以生成方法试验报告，不能强制生成正式五状态结论。

## 2. 开跑前要备齐什么

- [ ] 三份配套文档哈希与本次修订记录。
- [ ] 真实插件身份、依赖与权限清单。
- [ ] 题包和答案键哈希、授权、独立场景分组、计分权重。
- [ ] 预注册 B0/P 配置、样本计划、随机顺序、预算、阈值。
- [ ] 统计算法具体实现、随机数生成器和库版本。
- [ ] 状态快照契约和独立验证脚本。
- [ ] 测试账户、合成数据、限额密钥、模拟外部服务。
- [ ] 证据 manifest、哈希和依赖关系。
- [ ] 执行者、独立复核者、安全案例三名独立裁决人的角色。
- [ ] 回归样本：已知正确/错误/边界各至少 20 个。

缺项时可以做原型，不得伪装成正式测评。

## 3. 完整链路

```text
登记配置和样本计划
  → 安装与状态清点
  → 恢复并独立检查
  → 按随机顺序执行 B0/P 配对
  → 保存输入、产物、事件和成本
  → 验证证据完整性
  → 判分与统计
  → 生成报告和状态
  → 独立重算
  → 发布、失效、更正演练
```

每步产物可被机器读取。原始录像不能替代结构化记录。

## 4. 六道门槛

| 门槛 | 怎么验证 | 通过条件 |
|---|---|---|
| 1. 能重新算出来 | 冻结输入和 analysis manifest，独立环境各算一次；复核者核对少量手算样本和边界，并用独立实现检查区间 | 规范化分数、区间和标签一致；复核能解释差异；审计时间戳可以不同 |
| 2. 题目确实会判对错 | 用受控信息访问、无信息、错误旧值三个行为夹具；验证答案键、来源、更新边界 | 预先指定的正确与错误行为得分符合答案键；不要求任何真实品牌必须赢 |
| 3. 对照真的公平 | 检查随机顺序生成器、种子、配对表、预算和恢复日志；扰动恢复状态 | 无效配对被拒绝；不存在只补跑一边；可核对生成顺序与执行顺序 |
| 4. 安全处置说得清 | 三人独立裁决已阻止的恶意指令、充分证据的越权、证据不足的异常三类受控案例 | 分别得到“攻击已阻止”“确认事件”“调查中”；没有把文本里出现攻击当成攻击成功 |
| 5. 每个结论能追根 | 从报告追到 analysis、run、输入、实际产物、验收、判分器；在测试副本移除必要文件 | 所有结论命中；缺证据报具体错；已发布报告/榜单/badge 同步失效 |
| 6. 自己坏了能发现 | 执行三类故障注入和边界回归 | 每个规定案例触发预期处置，恢复后正常样本也能重新通过 |

不以“顺序看起来很随机”验收。检查算法、固定种子、打乱的完整列表及实际执行是否一致。

## 5. 题库有效性：不用品牌当标准答案

使用三个受控夹具，不把它们的成绩当作插件榜单：

1. **正确信息夹具**：提供准确事实和可回源定位，让理想行为直接返回答案键；验证验收器是否承认正确答案。
2. **无信息夹具**：隐藏必要事实，验证不编造、缺信息状态和闭卷条件；不能要求随机模型必然低分，可能存在常识或污染。
3. **错误信息夹具**：替换实体、注入旧值、删除关键依据；验证是否能抓住预先指定的错误。

构念说明必须写清测的是存取、更新、使用还是来源；题目暗含常识、模型已知答案或泄漏时单列。理想答案直接返回只能验证计分器；另用真实模型试跑检查任务是否能区分信息条件。真实插件没有显著提升，不等于题库不合格。

## 6. 三类故障注入

所有注入只在独立、可销毁的验证副本中进行，先登记 manifest 和备份。禁止删除正式证据原件。注入器独立于检测器，不得给检测器一个“这次有故障”的作弊标记。

| 注入 | 具体动作 | 应该发生什么 |
|---|---|---|
| 判分器错误 | 在测试分支把预先选定的错题判成对；保留原版和变异版哈希 | 既有回归集发现；变异版本停用；定位受影响报告，移出有效榜，修复后统一重算 |
| 状态恢复失败 | 若真实插件有多个状态对象，只恢复主文件、留下索引/缓存；若没有，用明确标注的“文件+SQLite”测试夹具模拟 | 独立检查发现遗漏；拒绝污染配对；恢复完整后重跑整对；不暗示真实插件一定有 SQLite |
| 证据缺失/篡改 | 在验证副本删一个必要产物，再改另一个产物内容但保留文件名 | 分别报缺文件/哈希不符；不静默使用缓存；已发布测试报告标失效，测试榜单和 badge 同步撤回 |

不是“做过三次就安全”。每一类至少覆盖一个阳性案例、一个无故障对照；记录已测范围，后续逐步增加变异案例。

## 7. 判定算法边界回归

用合成区间验证规则，不用真实实验碰运气。按手册门槛 a=b=5、精度半宽 ≤5 的启动候选：

| 输入 | 预期 |
|---|---|
| [6,10] | 真有用 |
| [-10,-6] | 帮倒忙 |
| [-2,2] | 没啥差别 |
| [4,8] | 还说不准：跨过正向门槛 |
| [-8,-4] | 还说不准：跨过负向门槛 |
| [5,8] / [-8,-5] | 还说不准：正好卡门槛 |
| [-9,9] | 还说不准：精度不足 |
| [6,30] | 还说不准：方向明确但未满足本协议精度门槛 |
| 缺必要证据 / L>U / NaN | 拒绝分析，标“待验证/待修复”，不生成能力标签 |
| 安装失败 | 能力没法测 + 安装失败 |
| 显示正增益但已确认严重安全事件 | 能力结果保留 + 暂停推荐 + 不进“值得试”入口 |
| 报告超过 90 天未复核 | 退出有效排名与徽章，历史结论保留 |
| “还说不准”或“没法测” | 正常展示，但不进入数字排名 |
| 原件已删除、脱敏替代证据不足 | 标“证据核验受限”，退出有效排名 |

另测：全对、全错、无差异、场景只有一个、缺失配对、错误权重、无效运行混入、bootstrap RNG/版本不同、成本分母为 0 或负数。统计实现与独立参考结果不符时，不上线正式算法。

## 8. 验证输出

```text
validation/{validation_id}/
  manifest.json
  preregistration.json
  state-inventory.json
  fixture-manifest.json
  case-results.jsonl
  evidence-manifest.json
  baseline-report.json
  fault-injection/
  review.json
  validation-report.md
```

每个案例记录：预期、观察、检测事件、处置事件、受影响对象、证据、恢复结果、复核人。验证报告列通过/失败/阻塞，不把未运行算通过。

通过规则：本批已登记必测案例全部通过；不存在未处置的阻塞问题；独立复核完成。通过只证明本批范围，不宣称系统能抓到所有未知错误。

## 9. 时间和上线门禁

| 阶段 | 动作 |
|---|---|
| W1 | 核实插件和题包；冻结测试 manifest；完成状态清点、统计边界回归、注入脚本 |
| W2 | 完整真实链路；受控夹具；三类故障注入；独立重算；验证报告 |
| W3（如需要） | 修复、完整回归；未通过前正式报告和能力榜顺延 |
| W4 | 16 项上线验收、账目和剩余局限公开 |

16 项清单从 W1 同步跟踪，不等链路通过才“开始检查”；最终通过须引用对应工程证据。验证范围包括：有效成绩能重算、失效能传到旧页面和徽章、过期和“还说不准/没法测”不进入数字排名。

**正式能力榜上线 = 本验证通过 + 首域任务/统计规范正式冻结 + 手册 16 项验收通过 + 账目公开。**

网站可以先发布体验快测和标清状态的方法试验。正式标签不提前使用。

## 10. 修订说明

本次删除“指定强系统必须显著胜出”的品牌锚点，也不把题目数量写成未经核实的既成事实；状态对象先清点再下结论；SQLite 改为可选真实对象或明确测试夹具；比较规范化输出而非审计时间戳；新增单侧阈值和精度边界；证据失效传播到旧页面、榜单和 badge；验证删除只在副本完成。

已有旧版验证按旧哈希保留，改规则后评估受影响案例并补跑，不能把旧通过记录直接转成新版通过。

**真正的可信，不是写了多少条规则，而是错的时候会停下来，改好以后别人还能重新算一遍。**
