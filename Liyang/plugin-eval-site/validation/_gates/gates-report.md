### 2.2 真实模型三条件试跑（生成器＝cline flash，温度 0.7，种子 1；同链路判分）
- 考卷 A（20 题，`gate2/real_A/summary.json`）：平均分 gold **0.50** / none **0.00** / wrong **0.05**；gold−none +0.50（95% 区间 +0.30～+0.70，10 好 0 差，符号检验 p=0.002），gold−wrong +0.45（+0.20～+0.70）。none 条件 19/20 在规则层因无依据直接 fail。wrong 条件唯一的 pass 是 answerable:false 的 o004（给错材料时模型如实说"无从得知"＝正确行为）。**结论：考卷 A 能区分信息条件。**
- 考卷 B（30 卡，`gate2/real_B/summary.json`）：平均分 gold **0.35** / none **0.35** / wrong **0.10**。gold−none **0.00**（95% 区间 −0.13～+0.13，8 好 7 差）；gold−wrong +0.25（+0.13～+0.37，14:1，p=0.001）；none−wrong +0.25（+0.12～+0.38）。gold 材料＝同一对话断点前 300 行原文（平均约 8,100 字，止于答案行前一行）；wrong＝另一文件同样长度的窗口。判分批上岗考第 1 次通过，题目一致率 0.96/κ 0.92。**结论：考卷 B 能抓住“误导材料帮倒忙”，但在这个 gold 定义下分不出“有正确上下文”和“闭卷”**——题面里断点前的「我说」两句已经给了生成器主要线索，更早的原文没有再加分。这与正式读数的形状一致（BM25 ❌、dsh 😐）：这张卷对“帮倒忙”敏感，对“真有用”的检出力存疑。局限：1 个种子、30 卡；gold 只试了一种定义。

### 2.3 门槛 2 判定：**失败（部分）**
预先指定的错误行为里有一类没被抓住：**替换实体**。B 的判官对"句式不变、关键实体全换"的答案 15% 给满分、75% 给半分；A 的规则层把关键词全中但主角/数字全换的答案直接判 pass，根本不交给判官。按计划 §4"预先指定的正确与错误行为得分符合答案键"——不符合。正确行为、无信息、旧值、删依据、退化条件的诚实轴都按预期。
另，真实模型试跑显示考卷 B 在本批 gold 定义下**区分不出正确信息与无信息**（只区分得出误导信息）；按计划 §5“真实插件没有显著提升不等于题库不合格”，这条本身不判失败，但它说明考卷 B 的 ✅ 检出力需要另行论证（换更强的 gold 条件、多种子）后才能用于正式能力榜。

| T1 | 改种子 | ORDER_NOT_REPRODUCIBLE |

随机数：Python `random.Random`（Mersenne Twister），种子与完整打乱列表、列表哈希都登记；检查器按算法+种子重生成后逐项比对，不以"看起来随机"验收。

**用已有 runs/B_* 实测（`audit_runs_B.json`、`audit_runs_A.json`）——哪里不满足 v3：**
1. **没有随机执行顺序**：`config.json` 无顺序种子、无打乱列表、无配对表、无预算、无补跑上限、无快照契约（三臂 6 项全缺）。`run.py` 按（种子，题卡顺序）固定提交线程池，只有并发 3 造成的相邻乱序。
2. **两臂不交错**：B0 与 P 各自整臂跑完。B_null vs B_dsh 同题同种子生成**中位相隔 88 分钟**（最大 92）；B_null vs B_bm25 中位 1.8 分钟（两臂同时跑）。时段与网关漂移没有被随机化抵消。
3. **两侧不同批判分**：每臂每种子单独一批（同 48 锚），B0/P 两侧由不同判官实例在不同时间判；盲于臂名，但未混批。
4. **无逐对恢复与独立恢复检查**：每臂一次 `Sandbox(fresh=True)` + 装后快照 diff。插件状态在 89 题召回间不重置；实测 dsh 每次召回都会追加 `_access.log`、`_heartbeat.jsonl`（`recall_state_mutation.json`；`_index.json` 不变），是否影响后续排序未验证。
5. **"只补跑一边"痕迹**：考卷 B 未见同题同种子重复作答（续跑判词走缓存）。**考卷 A 有**：08:34 并发事故后只对 A_bm25/A_dsh 的部分判分批剔缓存重判，A_null 未重判；A_bm25 s1 另因改锚作废 2 次——而 `judge/s1.json` 里 attempt=1、voided=0，作废历史只在 OVERNIGHT/录像里，不在批产物里。
6. 正面：生成/判分续跑靠断点与缓存，没有偷换题或缩分母的痕迹。

**判定：检查器通过（本批）；既有 runs 不满足 v3 公平要求**（缺少检查器所需的预登记，它们不能作为严格配对证据）。

## 发现的系统缺陷（按严重度）

1. **替换实体抓不住（门槛 2 失败原因）**。B：判官对句式不变、实体全换的预测 3/20 给 strict、15/20 给 paraphrase（=0.5 分）——"表面像"被当成"内容对"。A：上游规则层的关键词表不含人名/数字，换了主角/数字照样 pass，**且 pass_rule 不交判官**。诊断显示：即便送判官，覆盖率判官也放过 11/13 替换实体、10/10 编造断言（只数要点、不罚错实体与多余错话）。
2. **A 规则层的"编造模式"正则过窄**：断言卡片登记的编造模式 10/16 被直接放行。
3. **A 正确答案被卡片自己的反模式正则误杀**（q030：引述抱怨原话触发 `(早该加上|后来才加).{0,10}(记忆屏蔽)`，否定检测没生效）——上游判分器假阴性，建议写入 UPSTREAM_SUGGESTIONS（本代理未改该文件，越出文件归属）。
4. **双判官不独立**：同一模型、温度 0 的两个实例在本批 B 夹具 148 条（含锚）上 100% 同判，"双判官一致率"在这里几乎不提供信息；上岗考只能抓整体漂移，抓不到定向错误（6①）。
5. **v3 公平要素缺失**（门槛 3 第 1–5 条）：无随机执行顺序与登记、两臂不交错、两侧不同批判分、无逐对独立恢复检查、考卷 A 判分重判只在 P 侧、作废历史不在批产物里。
6. **证据治理**：报告结论所依赖的 B_null 原始运行只在 gitignore 的 `runs/`；没有正式的 evidence manifest / 撤销表 / 失效传播（本批在 `tools/gates/` 实现了最小版本，尚未接入正式发布流程）。
7. **安全裁决缺可执行风险映射**：状态一致而威胁类别/严重度各说各话（门槛 4）。
8. **考卷 B 对“有用信息”无区分力（本批）**：真实模型 gold（断点前 300 行原文）= none（闭卷）= 0.35，只有误导材料降分——这张卷能检出“帮倒忙”，“真有用”的检出力未得到支持。
9. 考卷 B 的分数不含来源轴：内容＝答案键、依据清空仍得满分（夹具"删依据" 20/20 strict），来源只在机械依据轴单列——构念上 B 测"使用"，不测"来源"，报告须写清。
