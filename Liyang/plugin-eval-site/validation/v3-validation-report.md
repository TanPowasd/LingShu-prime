- 运行出问题还硬算：两次真实环境故障都触发整对作废、按预注册补跑，丢失的读数不进分析（§5、§11）。
- 只补跑一边、换执行顺序、事后改登记、超补跑上限、超预算（门槛 3 检查器）。
- 证据缺失/篡改照样出数：报具体错、拒绝重算、报告/榜单/徽章同步失效（门槛 5、6③）。
- 状态没恢复干净就配对：真实插件上拒配（门槛 6②）。
- 判分器被定向改坏：冻结回归集抓到（门槛 6①）。
- 畸形输入、NaN、L>U、错误权重、RNG/版本不一致：拒绝分析（§3）。

**还挡不住**
- 判分器把"像而错"判对：替换实体（v1）、相反断言（v2 也抓不住）——这是今天最大的可信度缺口，所有现存分数都受影响。
- 考卷 B 分不出"真有用"（gold = none），只对"帮倒忙"敏感。
- 同模型双判官的一致率没有独立性；v1 上岗考抓不到定向判分错误。
- 人：独立复核、真人安全裁决都没有；执行者知道被测身份（非盲）。
- 仿真宿主偏差（无 agent 循环）、题包授权未核实、公开题包的模型污染。

**正式能力榜还差**（计划 §9：验证通过＋首域规范冻结＋16 项通过＋账目公开）
1. ≥8 个独立场景的授权题包冻结——考卷 C（LongMemEval，MIT，495 场景）是现成候选，须走公示/冻结，补 flash 判官人工一致率校准，并先裁定 R3（成本）。
2. 判分器过门槛 2：v2 补极性检测、重新预登记与上岗；漏判样本进冻结回归集。
3. 记忆域判定规范冻结：权重、场景权重、补跑上限、a/b 校准、成功定义（R7、R8、R12）。
4. 指派独立复核者与三名真人裁决人，重做门槛 1、4 并签 `review.json`。
5. harness 主出口改 v3（唯一 run_id、§13.3 证据目录、预注册与补跑上限），旧 runs/ 不再作严格配对证据。
6. 16 项验收（现 0 项经复核）与账目公开；R1–R13 勘误裁定。
