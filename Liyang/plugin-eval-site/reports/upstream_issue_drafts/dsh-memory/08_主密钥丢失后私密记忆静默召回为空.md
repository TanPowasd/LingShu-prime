# [Bug/Data loss] 加密主密钥（`~/.mdcg/master.key`）与记忆库分居；主密钥缺失时私密记忆召回静默变空、无任何报错

> 状态：**草稿，未提交**。被测 sha `c8c3655`。
> **是否已有人报**：未见同题（2026-10-10 查 issues 列表 81 条）。

## 环境
见 `_公共环境.md`；designer + `--clearance private` 令牌（会话摄取节点缺省 private、正文加密）。

## 复现步骤
1. 空 `MDCG_ROOT`，用 private 令牌 `cg(op=ingest, action=jsonl)` 导入一份 50 轮会话。
2. `mdcg_recall {"query": "公式符号复制后保存到md里乱码", "k": 5}` → 记下命中。
3. 停服务；把 `~/.mdcg/` 移走，只把 `_tokens.json` 放回新建的 `~/.mdcg/`（模拟"备份/迁移了 MDCG_ROOT 但没带走 HOME 下的密钥"）。
4. 重启服务，同一查询再召回。

## 期望
主密钥缺失或与库不匹配时，服务启动或召回时明确报错/告警（如"N 个加密节点无法解密"），而不是返回空结果；文档写明主密钥位置与备份要求。

## 实际
- 步骤 2：命中 1 条（`公式符号复制乱码原因.md#L3-L39`，1,185 token）⟦录像:dsh_key@00:07#15⟧。
- 步骤 4：命中 0 条，`tokens_used 0`，服务正常握手、无错误字段 ⟦录像:dsh_key@00:08#16⟧ ⟦录像:dsh_key@00:08#17⟧。
- 主密钥在 `~/.mdcg/master.key`（44 字节），记忆库在 `MDCG_ROOT`，两处分居（卸载残留快照 ⟦录像:dsh_install@00:23#79⟧）。README 称记忆"任何编辑器可直接打开审阅"（本站报告摘录，提交前对照 c8c3655 README 原文），对 private 加密节点不成立。

## 影响
用户只备份/迁移 `MDCG_ROOT`（直觉上的"记忆库"）→ 换机后所有私密记忆**静默不可召回**，看起来像"什么都没记住"，没有线索指向密钥。

## 建议
- 启动时检测"库内有加密节点但无可用主密钥"并告警；召回时对无法解密的候选计数并在返回体给出。
- README 增"数据与密钥"一节：两处路径、备份/迁移须同时带走、丢失后果。
- 可选：允许把主密钥放在 `MDCG_ROOT` 外的显式配置路径并在 `--show-config` 中显示。
