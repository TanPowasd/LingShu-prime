## 什么人适合装

能力分已出：在这套真实聊天续接卷上，装不装 dsh-memory 判不出差别（😐）；它比同卷的朴素 BM25 好（BM25 在这卷上是帮倒忙），可能的原因（推断，未单独验证）是它缺省只注入约 2 千字的短材料、对生成器干扰小，而不是召回得准——召回高度集中在少数枢纽块（见「检索面观察」）。据此：

- **适合**：已经在用 DSH（或愿意手动配 MCP），记忆量不大（几百到一两千条），看重"记忆可审计、可撤销、私密内容落盘加密"的人；愿意读报错 hint、自己补签令牌的开发者。
- **不适合**：想"一条命令装好就用"的人（推荐的一键命令在 Linux 上静默不干活）；要把几千轮历史聊天一次性导进来再随问随答的人（8 千轮规模下单次召回约 1 分钟）；不想管密钥备份的人（主密钥放在 HOME 下另一处，丢了记忆就静默召回不到）。

## 单子二：好不好用（安装与文档）

在干净的隔离环境（独立 venv、临时 HOME、独立 MDCG_ROOT，都在 /tmp）里，照 README 的"一键配置（推荐）"+"其它 MCP 宿主 → 直接挂载大脑"+"写入凭据"三节走一遍。完整录像：复核包 `录像/install_时间轴.md`。

**走到"第一次成功把一段会话导进记忆"一共要 7 步，其中 4 步失败**，有两次失败**完全没有提示**。

| # | 步骤 | 结果 |
|:--|:--|:--|
| 1 | `git clone`（README ①） | ✔ 3 秒 |
| 2 | `npx @furongjun1999/dsh-memory init -- --end generic …`（README "一键配置（推荐）"） | ✘ 无输出、exit 0、不写片段 |
| 3 | 绕过：直接 `node <npx 缓存>/lib/cli.js init …`（README 没写，是我们读源码找到的） | ✔ 产出 mcp.json 片段 |
| 4 | 照抄 README 令牌命令 | ✘ rc=127（Windows 语法） |
| 5 | 改成 bash 单行重签 | ✔ |
| 6 | 用 README 令牌导入会话 | ✘ 拒绝（权限白名单 / 密级），或静默拒绝 50/50 |
| 7 | 按报错 hint 重签 `designer --clearance private` 后导入 | ✔ 50/50 写入；但在第 6 步用过的库上重试 → 0 条（被拒事件已推进水位） |

扣分点：

- 【扣】README 主推的一键配置 `npx @furongjun1999/dsh-memory init` 在 Linux 上**静默空转**：无任何输出、退出码 0、不生成 `lingshu-mcp-snippet.json` ⟦录像:dsh_install@00:06#12⟧ ⟦录像:dsh_install@00:07#35⟧。源码已于 2026-10-09 修复（commit `29e24da9`，issue #97），但 npm 上同一版本号 0.8.1 的包仍是旧代码，直接 `node` 执行同一个 cli.js 就正常 ⟦录像:dsh_install@00:07#38⟧。
- 【扣】README "写入凭据"的命令是 Windows cmd 语法（`^` 续行、`setx`），Linux/macOS 照抄直接失败 ⟦录像:dsh_install@00:06#21⟧；README 正文没有 bash 写法（只有 init 的输出里有一句"把 ^ 换成 \"）。
- 【扣】文档自相矛盾：init 生成的片段写 `MDCG_CLEARANCE=private`，README 的令牌命令签 `--clearance internal` ⟦录像:dsh_install@00:07#38⟧；服务启动时告警"令牌优先"，以 internal 为准。
- 【扣】按 README 签的令牌导入会话：`cg(op=ingest)` 被权限白名单拒绝 ⟦录像:dsh_install@00:12#47⟧，而同一令牌改调细粒度工具 `mdcg_ingest` 却**不受白名单约束**，进到写入层才因密级不够 50/50 被拒 ⟦录像:dsh_install@00:13#50⟧——两条入口的权限口径不一致。
- 【扣】**静默丢数据**：会话摄取被拒时，被拒的事件照样推进"已摄取水位"；换上正确令牌重试，`new_events=0`，这批对话永远不会再被导入，且没有任何提示 ⟦录像:dsh_install@00:20#65⟧ ⟦录像:dsh_install@00:21#68⟧（对照：在没被拒过的新库上同一令牌 50/50 写入 ⟦录像:dsh_install@00:17#59⟧）。
- 【扣】README 称 `--role recorder` 是"最小权限版"，但 recorder 根本导不了会话（会话缺省密级 private，非 designer 角色上限 internal）⟦录像:dsh_install@00:15#53⟧。
- 【扣】DSH 自动记忆的缺省写入通道 `mdcg_remember(gated=true)` 有限流：60 秒内第 9 条起判 DEFER；返回体仍带 `node_id`，但这个节点并不存在 ⟦录像:dsh_retire@00:06#30⟧ ⟦录像:dsh_retire@00:06#31⟧。连发 25 条用户消息只落盘 8 条，其余 17 条判 DEFER（按 md_cg/forgetting.py 语义＝不写入、只留痕待复核） ⟦录像:dsh_install@00:23#71⟧。
- 【扣】README 没有卸载章节 ⟦录像:dsh_install@00:23#75⟧。
- 文档与实现不符（代码证据，非录像）：README 写"自动召回注入 → `mdcg_recall`"，DSH 运行时实际注入的是 `stg(op=timeline)` 最近 4 条（`src/hooks.ts:608-631`）。

做得好的地方（如实）：零 pip 依赖、纯标准库，clone 后 1.5 秒内即可握手 ⟦录像:dsh_install@00:08#41⟧；`--show-config` 自检好用；每个权限拒绝都给出"缺哪个 op、怎么重签"的具体 hint；写入返回体区分 `ok` 与 `committed`，README 也反复提醒"别把 ok:true 当写成功"。
