## 剖析（`_stab/r15/prof/`；rel-v1.29 的剖析见 CHANGELOG_rel-v1.29 与 `_stab/r14/prof/tm_B0_10000.txt`）

rel-v1.29 时 tracemalloc（vs_worker 同流程：写 10k → 200 查询 → 衰减 → 50 次晋升）Python 侧前两名：
`lexical._tokens` 缓存 10,178 条约 23.7 MB（已驻留的词元串 16.7 MB + 元组 5.0 MB）、`dedup.bigrams` 缓存 1024 条约 11.6 MB（frozenset 表 + 二元组串）。

- 分词缓存的大头不是元组，而是**被元组留住的十余万个短词元串**（中文正文按相邻两字切，10k 库 158k 个不同串，每个 2 字的 str 对象约 80 B）。
  词元以空格连成一个串后，这些短串在缓存里不再存活；中文段再进一步只存整段（相邻二元组取用时展开），10k 时该缓存约 23.7 → 约 2.8（终版 `prof/tm_final_10000.txt`，lexical.py 合计） MB（`prof/tm_final_10000.txt`）。
- 二元组缓存的 frozenset 主要被两类调用方复用：写入期近重复判定（命中率约 2/3）与 `assoc._neighbors` 只取个数 `len(bigrams(c))`（1k 召回时约 3.9 万次）。
  第一版只缓存规范化串、按需建 frozenset 时，1k 召回 p50 3.71 → 6.68 ms（`pre1/`，cProfile 定位到 `_neighbors`）；改为另设只存整数的 `bigram_count` 后回到 3.59–3.83 ms（`pre2/`、`pre3/`）。
- tmprof 的 RSS 读数不能直接用：它在写入后持有一份 tracemalloc 快照，查询阶段 RSS 的增长主要是快照本身；本轮的内存判定只用 vs_runtime 与 perf_bench 两个口径。
- rel-v1.29 试过的 `sys.intern` 二元组串（内存更大）本版未再用。

## 改了什么

1. **`lingshu_ng/lexical.py`**：`_tokens`（lru_cache，键与上限不变）的缓存值由「驻留词元串的元组」改为单个紧凑串：段以空格相连，拉丁词段即词元，中日韩段存整段；
   `tokens()` 取用时按空格切开，长度 ≥3 的中日韩段展开为相邻二元组（长度 1 / 2 的段即其唯一词元）。词元来自分词正则的 CJK 段或 `[^\W_]` 词段，永不含空格、永不为空串，拉丁段不含中日韩字，
   所以往返与旧切分同序同值；全 ASCII 时直接 `split`。去掉 `sys.intern`（词元不再长期存活于缓存，驻留没有意义）。
2. **`lingshu_ng/dedup.py`**：`bigrams` 不再缓存 frozenset，改为缓存规范化串（`_bigram_src`，上限仍由 `LINGSHU_NG_BIGRAM_CACHE` 定，与 `normalize` 缓存共用同一串对象），按需用 `map(operator.add, s, s[1:])` 建 frozenset；
   `bigrams.cache_info` / `cache_clear` 仍可用（指向 `_bigram_src`）。新增 `bigram_count(text)`（只缓存整数）。`jaccard` 对已是集合的参数不再复制，并集大小按 |A|+|B|−|A∩B| 计（整数相同，商逐位相同）。
3. **`lingshu_ng/assoc.py`**：`_neighbors` 用 `bigram_count`；`_jac` 并集大小按 |A|+|B|−|A∩B| 计（不建并集）。
4. **测试**：新增 `tests_ng/test_cache_compact.py`（3 条：随机混合文字 3000+ 条 × 4 种 stem/stop 配置下 `tokens` 与内联的旧算法逐值相同、命中路径相同；缓存值为紧凑串；`bigrams` / `bigram_count` / `jaccard` 与旧算法逐值相同）。
   另有一次性核对 `_stab/r15/tok_eq.py`（对 rel-v1.29 树直接导入）：语料 3 万条 + 随机 20 万条 × 4 配置共 92 万次 `tokens`、6 万次 `bigrams` / `bigram_count`、17.7 万次 `jaccard`（含列表 / 重复元素参数）差异 0。
