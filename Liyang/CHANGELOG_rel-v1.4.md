相对上次推送版（Liyang/ = rel-v1.3，LingShu-prime a744c9c / 发布树 rel-v1@93e53b9）的增量升级：只动版本链（`lingshu_ng/chain/`，`enable_chain` 仍为可选、缺省关）。

## 改了什么
- **v16 零 LLM 抽取（版本链开启时缺省生效，`LINGSHU_NG_CHAIN_V16=1`；=0 时与 v15 逐条相同）**（新文件 `lingshu_ng/chain/v16.py` + `ledger.py` 钩子）
  - **账本窗口抽取**：前面几条路径（规则、锚定、「主体 属性 值」、v15 外壳重抽）都没登记的句子，再按「已知主体 …（≤16 字、无句读）… 已确认属性 … 合形态的取值」找一次。
    主体前可以有虚词（把/关于/因…），取值可以在逗号后面（「A 现在定了，是 V」）；属性和取值的锚点可以来自整本账（别的命名空间确认过的属性和取值）；
    没登记过的中文取值只在（主体, 属性）已确认、或属性后紧跟判断词（是/为/定为/标成/记作…）时才收；「由/从 旧值 改…」里的旧值跳过；
    没写属性名的位置变化（「S 现驻/去了/迁至 L」）只认登记过的地点。假设、疑问、回顾旧值的句子不登记。
  - **动作判别**：改写后丢了句式信号词时，用还保留的语义信号判 set / resolve / unresolve——争议、之争、裁定、尘埃落定、终于、总算、最终/最后（叙述体「最后落脚/搬去/只剩」除外）判裁定；
    有两值信号又有未决信号（中英：还没、未定、没有结论、先别、no decision、not yet decided…）判未决并取两个值。只改已确认属性上的非严格事件，散文里原有的误登记不动。
  - **残片后修**：主体带残片（「今天S」「S决定」「将S」「【标签】嗯」）或是泛称（「项目」「项目里用到」）时取回已知名；主体和取值对调（信任对象类的取值本身也是人名）时，以紧挨属性名前的已知名为主体；
    属性带残片（「函数签名敲」「情绪上」「位置目前有」）或句中只有一个已确认属性时归一，「地点/去向/办公」类归到「位置」；
    取值做单位换算（30min→1800）、形态不合或落在起因里时在属性名之后重取、「鼓楼办公」「V 两个值并存」截回已登记取值、未决两值按句中出现顺序。严格句式事件只修残片，不改动作。
  - **提速**：v15 外壳重抽先查句中有没有已知名（重抽结果本来就要求主体是已知名，结果不变）；锚点按（命名空间, 记录数）缓存。
  - 写入期零 LLM。分项开关：`LINGSHU_NG_CHAIN_V16_WIN / _POST / _OP / _GLOB / _GLOBV / _COLD / _COLDG / _LOCA / _IDOK / _STRICT`（缺省全开），`_OPPREV`（缺省关，dev 净负）。
- B（受限 LLM 抽取，`LINGSHU_NG_CHAIN_LLM=1`）不变，仍缺省关。
