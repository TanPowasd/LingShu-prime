# CHANGELOG rel-v1.6（zh-v11c：中文联想通路自适应稠密补入设为默认）

相对上次推送版（Liyang/ = rel-v1.5，LingShu-prime d8ae585c / 发布树 rel-v1@fc4366e）的增量升级：只动**中文联想通路的语义重排段**（`lingshu_ng/semrank.py`、`AssocConfig` 四个字段）。
英文词级通路（gen-v3.2 + densefuse F3）、版本链（v16）代码未改；随合入带进 v8–v10 的可选开关代码（`sem_fuse`、`sem_disc`、`sem_ans`、`lingshu_ng/anstype*.py`），全部缺省关。

## 改了什么
- **v11c = v7.1 + 自适应稠密补入**（PREREG_ZH 修订 9 设计、9b 冻结、9c 判定）。`AssocConfig` 缺省 `sem_dense=20, sem_dense_m=5, sem_dense_cap=2, sem_dense_tau=0.0`：
  - 词面头部经 bge-reranker 打分后，logit ≥ τ（−3.25）的段**少于 5 条**时，才按 bge-small-zh-v1.5 稠密余弦从全库补入前 20 个候选（词面召回不足才走语义；思想来源：BGE-M3 稀疏+稠密混合检索）；
  - 补入段须 reranker logit ≥ 0 才保留（`sem_dense_tau`），且补入被触发时截断后取段数 ≤ 2·sem_min（`sem_dense_cap`），控制误用；
  - 链式请求（「从最初到现在…」）不补；库超过 5 万块不补。
- 逐位回退：稠密件（bge-small-zh ONNX）不可用 ⇒ 与 v7.1 逐位相同；打分件（bge-reranker-base）不可用 ⇒ 与 v4 逐位相同（新单测 `test_default_without_embedder_is_v71`、原 `test_default_without_scorer_is_v4`）。

## 怎么定的（只在 dev 上选；保留集只跑一次）
- 候选族 m ∈ {1..5} × cap k ∈ {0,1,2} × τd ∈ {关,−1,0,1}，60 格离线模拟（零 LLM）；选择规则读数前写定：T2R2 r1dev 误用增幅 ≤ +.0025、DuRT dev 无显著变差且取段增幅 ≤ 3%，取 S（Δ召回+Δ全证据+ΔnDCG+ΔMRR）最大者。引擎与离线模拟在 DuRT dev 200 上 196/196 逐题一致。
- 照实：「补入上限」设计受上一轮（v10c）对 r1test 3 道题的事后分析启发；r1test 已是暴露的门集，本轮只用它判门。
