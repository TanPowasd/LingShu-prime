### 1.3 容量理论：为什么不能简单地「把所有日期都写进 TIME」（THEORY §4、I7 的直接推论）
- 同一角色叠加 m 个填充（无区分键）：解绑后各填充点积均为 `D + N(0,(k−1)D)`，两个真填充之间的余弦间隙 ~ `|N(0, 2σ²)|`（σ = 1/√D）。
  `P(间隙 ≥ MARGIN_MIN = 2σ) = P(|Z| ≥ √2) ≈ 0.157` ⇒ m=2 时约 **84% 存疑、16% 在两者之间近似掷硬币**（推断，独立高斯近似）。
- 已有实证：`RESULTS_seg.md` §诚实结论 3——LoCoMo 上 S1 把多轮装进一条痕迹后，多个 TIME 填充叠加，解绑取到别的轮的时间（S1 答对 11 / 错 37，S0 28 对）。
- 所以「多 TIME」必须带**区分键**（选项 A）、或拆成**每痕迹一个 TIME**（选项 B）、或**出向量层**做选择（选项 C）。朴素多填充（记作 A0）不列为候选。

## 2. 选项

共同前提（所有选项）：检索痕迹（`Memory.texts / toks`、RI 共现、idf）**不变** ⇒ E1 逐位 ≡ L1（`search_many` 只用内容向量 V，V 只由词序列决定；可写成运行时断言）；
第一版**只作用于长单元（> K_MAX）**，短单元逐位 ≡ 现状（是否扩到多日期短单元，留作决定点 ③）。

### A　句级时间绑定（单痕迹、键控多槽）
- **机制**：块痕迹里把 `R_TIME ⊗ F_f` 换成每个带日期句 j 一项 `R_TIME ⊗ F_{f_j} ⊗ K_j`，`K_j = sign(Σ_{w∈句j} I_w)`（句键，RI 索引向量，零模型）。
  解绑时用问句键 `K_q = sign(Σ_{w∈问句∩词表} I_w)`：`y = R_TIME ⊗ K_q ⊗ T`，`y·F_{f_j} ≈ D·c_j + N(0, kD)`，`c_j = cos(K_q, K_j)`；对块内日期码本清理，边距不足 ⇒ 存疑。
- **改动面**：`memory.Memory.trace`（新增键控项编码）、`Memory.decode` / `decode_unit` 增加问句参数；`seg.make_elems` 需保留句级 (句词, 日期)；`real_v2.answer_time` 旁新增带问句的作答函数（旧函数不动，保历史读数）。
- **容量代价**：每个日期句 1 项（与现在的 1 个 TIME 项同计入 K_MAX，块多 m−1 项，可忽略）；但判别要求 `c* − c' ≥ 2√k/√D`：k=25 时 0.10、k=120 时 0.22、**k=221 时 0.30**。
  句键是符号向量叠加的 sign，问句与目标句共享 3/4 个问句词、与干扰句共享 1 个时，`c ≈ 0.25 vs 0.08`，对比度 ≈ 0.17（推断，`(2/π)·arcsin(o/√(ab))` 近似，a=4、b=15）——
  **在装满的块（k≈221）上大多会落到存疑**，在小块上可用。
- **对现有读数的风险**：E1 无（见共同前提）。E2：PerLTQA first 类（L1 17/20）中多日期单元的 TIME 项被键控后，问句键与抬头句对比度不足时会从「答对」变「存疑」⇒ 有倒退风险（推断，量级未知，存疑）。
- **守卫 / 变异**：`I-A1` 键控解绑定例（问句键 = 目标句键时取回该日期、边距 ≥ MARGIN_MIN）；`I-A2` 容量曲线（理论守卫，同 I2 写法：`E[y·F_j]/D` 与 `c_j` 相差 < 容差，k∈{25,60,120,221}）；
  `I-A3` 问句与所有句零重叠 ⇒ 必须存疑（不回退抬头、不静默）。变异：忽略问句键（`K_q := 1`）→ I-A1/I-A3 变红；去掉句键（退化为 A0）→ I-A1 变红。
- **零模型可行性**：可行（只用 RI 索引向量）。**最「VSA 原生」，但理论上在长块上判别力不足**——它是本方案里唯一需要先在合成容量曲线上过关才值得做 dev 的选项。

### B　时间锚点子痕迹（按日期边界切子块，每子块一个 TIME；仅供解绑）　← 推荐
- **机制**：对长单元，按句流切「时间子块」，每个子块**恰好一个 TIME**，不进检索库，只在解绑时用：
  1. 初始锚点 = 单元首个日期（文档抬头）。
  2. **句首日期**（句子以日期开头，如「3月5日：…」）开启新锚点段，其后无日期的句继承该锚点（日志式文档）。
  3. **句中日期**（如「…须在 4月20日前完成」）只对**本句**成立：本句单独成一个子块（TIME = 该日期），下一句回到当前锚点。
  4. 每个子块 = 成员句词 ∪ 一个 TIME 项 ⇒ I7 判别力不变（THEORY §7.2「一条痕迹一个 TIME」不变量原样保留）。
  - 单元内选子块：候选单元的子块按「问句内容向量 · 子块内容向量」余弦降序（VSA 自己的相似度，`Memory.vectors` 同一 RI 投影），依次解绑 TIME，取第一个非存疑；
    问句与全部子块余弦 ≤ 0 ⇒ 显式回退到现行 `decode_unit`（来源字段标 `fallback`，不静默）。
  - 锚点规则 2/3 是**策略选择**（决定点 ②）：备选 B-i「只认单元首日期，正文日期一律单句子块」、B-ii「每个日期都开新锚点、后文继承最近日期」、B-iii = 上述句首 / 句中区分（推荐）。
- **改动面**：新增 `seg` 内一个纯函数（如 `seg.time_anchor_blocks`，句流 → 子块）；`Memory` 增加只读的子痕迹表（不进 `texts / toks / ri`）；新增带问句的单元解绑（如 `Memory.decode_unit_q`）与作答函数（`real_v2.answer_time` 不动）。
  `memory.extract_time_v2` 不动（子块内仍用它取「句内首个日期」）。
- **容量代价**：子块比块小（每个 ≤ 所在块），K_MAX 不成为约束；每个子块多存一个 D 维整数向量。PerLTQA dev 只有 68 个长单元含 ≥2 个日期（1.2 表），额外子痕迹数推断为数百量级。
  不在一条痕迹里叠多个 TIME ⇒ **没有 1.3 的多 TIME 干扰**；顺带把 PerLTQA 现行 L1 里 63 个多 TIME 块拆开（推断：这部分可能把现在的「存疑」变成答案，方向存疑）。
- **对现有读数的风险**：E1 无（子痕迹不进检索库，断言 RI 共现矩阵 A、idf、`search_many` 分数逐位 ≡ L1）。LoCoMo / hive / crossproj-zh dev 无长单元 ⇒ 逐位 ≡（断言）。
  PerLTQA E2：first 类 20 题里证据单元为长单元且含多日期的，问句若与某正文日期句更像，会从抬头改答正文日期 ⇒ 倒退风险集中在这里（推断，可在 dev 上逐题核对）。
  (b) 类「哪一天的纪要里记下的」：若被问的条目本身含句中日期，B-iii 会答该日期而不是抬头——这是 (b)/(c) 的固有歧义，B 不解决（决定点 ⑤）。
- **守卫 / 变异**：`G-B1` 范围：≤1 个日期的单元、短单元不产生子痕迹，解绑逐位 ≡ 现状；`G-B2` 每个子痕迹恰好 1 个 TIME 项、≤ K_MAX；
  `G-B3` 检索库不变（RI 的 A、idf、`search_many` 分数逐位 ≡ L1）；`G-B4` 锚点定例（抬头 + 句中截止：截止句单独成块、下一句继承抬头；日志式句首日期：后文继承最近句首日期）；
  `G-B5` 选择定例（问句贴近截止句 ⇒ 截止日期；贴近无日期条目 ⇒ 抬头；与全部子块无关 ⇒ 来源 `fallback`）；`G-B6` 确定性。
  变异：子痕迹写进检索库 → G-B3；句中日期当锚点（B-ii 行为）→ G-B4；选择忽略问句（取第一个子块）→ G-B5；子块并多个 TIME → G-B2；范围泄漏到短单元 → G-B1。
- **零模型可行性**：可行（规则切分 + RI 余弦 + 现有解绑 / 清理）。

### C　解绑时按问句在块内就近选日期（向量层之外的符号选择）
- **机制**：写入时为长单元保留一张句级表 `[(句序, 句词集, 句内日期或空)]`；作答时对候选单元，取与问句词重叠最多（BM25 或词重叠，平局按句序）的句：
  该句有日期 ⇒ 用它；否则取**该句之前最近的日期**（就近），再无 ⇒ 单元首日期。TIME 角色与痕迹完全不动。
- **改动面**：最小。`Memory.write` 旁存句级表（审计字段），新增作答函数；不碰 `trace / decode / codebooks`。
- **容量代价**：无（不进向量）。
- **对现有读数的风险**：E1 无。E2：「之前最近日期」在条目式文档里会把**上一条**的截止日期借给本条无日期的事实（(b) 类与 first 类直接受害，推断：在 crossproj-zh-long 式「条目乱序、截止日期散落」的文档里很常见）；
  这条就近启发式本身就是策略选择，且失败是**静默**的（没有边距可判存疑）。
- **守卫 / 变异**：`G-C1` 就近定例（含「前一条有截止、本条无日期」的反例，必须回到抬头还是借前一条——取决于选定规则，定例写死）；`G-C2` 无重叠 ⇒ 显式回退；`G-C3` 确定性 / 平局规则。
  变异：总取首日期 → G-C1；就近改为「之后最近」→ G-C1。
- **零模型可行性**：可行。**但答案不再来自 VSA 解绑**——它是挂在 VSA 旁边的符号表，存疑语义（I7）在这条通路上消失；用它就等于承认「VSA 角色只适合一单元一值」（诚实边界，推断）。

### D　维持现状（承认边界）
- **机制**：不改算法；在 `THEORY.md` §7.7 / `README.md` 写明「每单元（L1 下：每首块）至多一个 TIME = 文中最先出现者；正文日期题会被确定性地答成首日期」。
  可选 D′：单元含 ≥2 个日期时把 TIME 答案标成「存疑」——**不推荐**：(b) 类与 PerLTQA first 类也在多日期单元里，D′ 会把它们一起变成存疑（推断：PerLTQA first 类 17/20 中多日期单元那部分全失）。
- **改动面**：仅文档；若加一条守卫，锁定「正文日期题答首日期」这一已知边界（防止以后被无意改变而不自知）。
- **容量代价**：无。**对现有读数的风险**：无。**零模型**：是。
- **代价**：正文日期题恒错（crossproj-zh-long (c) 0/20 即其写照）；真实 dev 上这类题只有 5/104（1.2），所以在现有真实集上的损失很小——是否值得改，取决于用户的目标场景是否有大量「粘贴长文档再问正文日期」。

### 推荐（留给用户决定）
**推荐 B（锚点规则 B-iii，第一版只作用于长单元）**。理由：
1. 唯一同时满足「答案仍来自 VSA 解绑 + 清理边距（I7 存疑语义保留）」与「不在一条痕迹里叠多个 TIME（避开 1.3 与 `RESULTS_seg` 已实证的干扰）」的选项；
2. 检索库不动，E1 逐位不变可写成断言；只作用于长单元，LoCoMo / hive / crossproj-zh dev 逐位不变——风险被圈在 PerLTQA 长单元的 E2 上，可在 dev 逐题核对；
3. A 在理论上就卡在 K_MAX 附近的对比度（推断），值得先做一条合成容量曲线再决定，不宜直接上；C 最省事，但它让 VSA 在这个问题上「让位给符号表」，且失败静默；
4. D 是诚实的底线；若用户的目标场景很少有「正文日期」问题（真实 dev 只有 5/104），D 完全合理。
