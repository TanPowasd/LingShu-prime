## 诚实结论

**成立的：**
1. 「te 召回 + VSA 解绑」在 LoCoMo dev 时间题上把端到端从 0.28 提到 0.56（J2，p=0.0026；阶段 1 严格判定 J1 下 0.18 → 0.32，p=0.065 不显著）。
   这是规则 + 候选 + 「显式时间优先」三件事叠加的结果，单项都不显著；且 v2 规则是在同一 dev 上看过阶段 1 失败后设计的 ⇒ **乐观的开发集读数**。
2. 存疑阈值第一次承担了真实决策：TIME / SESSION 分开后，「这轮有没有说时间」由清理边距直接判定（守卫 G13 的变异证明关掉阈值即吐随机日期）。
3. 合成集上，多跳（交集、链式）在规则抽对时精确且与符号查找等价；BM25 结构上做不到。

**不成立 / 受限的：**
1. 在阶段 1 的严格判定下没有显著提升；J2 的等价换算（星期换算、无年份日期、拼写容错）本身贡献了 A0 从 0.18 → 0.28 的一部分。
2. PerLTQA 中文旁证没有可用信号（0.148，oracle 0.167）：长单元超过 K_MAX 被拒写，**必须先做分块**才谈得上解绑。
3. 合成集上 VSA 的全部优势都建立在抽取规则之上；规则外改写（C4）VSA 显著差于 BM25。

## 下一步建议（需另写预注册）
1. **分块写入**（PerLTQA 的硬瓶颈）：长单元按句切块，每块 ≤ K_MAX，块共享单元号与 SESSION；候选仍取 te10 的单元，再在其块内解绑。
2. **时间规则 v3**（只修读数后发现的 3 个缺陷，且换集验证）：将来标记只看时间表达所在分句、排除 "next to"；一轮多个时间表达时按「与问句动词/实体共现的分句」选，而不是最先出现。
   必须在 LoCoMo 之外的集（如 LongMemEval dev 的时间题）上报，避免继续在同一 dev 上拟合。
3. **显式时间优先的门控**：只在候选轮与问句的探针点积（人名 / 实体命中）不低于首候选时才越过首候选——用 VSA 自己的结构匹配挑轮，而不是只看「有没有时间」。
4. 粒度：问句是 "When" 时金标粒度不可知，属于金标习惯问题；不建议再加规则去猜（策略选择，needs-owner-decision）。
