# crossproj-zh v0.1 数据卡

**一句话**：一个人（林知远，38 岁，杭州产品经理）在约 6 个月里同时推进 6 个项目，与 AI 助手聊了 48 场；测记忆系统能否在多项目交织、事实不断更新、同名/同词跨项目混淆的情况下找回正确证据。

## 世界
- 项目：P1 青禾 App 2.0 上线｜P2 文三路老房装修｜P3 女儿小升初｜P4 开源副业 piko｜P5 云南家庭旅行｜P6 父亲复诊与自己减脂｜P0 家庭财务（共享 20 万预算池）
- 60 个事实槽位、80 个事件（含 20 次更新，最多改 3 版）；会话日期 2026-03-02 至 2026-08-23，每 3–4 天一场，共 652 轮。
- 刻意设计的交叉：两个「王磊」（青禾技术负责人／老房电工）；「验收」（青禾 UAT／装修竣工验收）；「游泳」（小满暑假班／林知远减脂）；装修验收推迟 → 旅行改期；复诊与测评同日 → 复诊改期；父亲做检查 → 不去旅行；预算池被装修和旅行共同消耗；陈默同时是 piko 合作者和家教介绍人。
- 第 38、44、47 场是纯闲聊干扰会话（无新事实）。

## 生成方式
1. `world.py`：真值手写（槽位、取值、更新顺序、所在会话），程序校验更新时序。
2. `render.py`：LLM（cline-pass/kimi-k3）逐场把事件写成对话；每条新事实必须由林知远在被标注的那一轮原样说出取值字符串；禁止编造新的具体实体；禁止出现未来才会出现的取值。代码校验不过则带错误反馈重试（48 场全部一次通过）。
3. `assemble.py`：程序出题，金标由程序回填 dia_id。
4. `zero_overlap.py`：LLM 改写问句，代码校验与全部有效证据轮汉字二元组/英数词零交集且不含答案。
   `verify_zo.py`：另一次 LLM 调用只看原问句/改写/答案判等价与唯一可确定；不等价者重写一次再判，仍不过则丢弃（60→54）。
5. `finalize.py`：按题型分层 20/80 划分 dev/hold，零重叠题与源题同侧；写 sha256。

## 题型
| 类别 | 含义 |
|---|---|
| single_fact | 单项目、只出现过一版的事实 |
| update_latest | 改过的事实问最新值（旧值作干扰） |
| update_first | 改过的事实问最初值 |
| temporal_asof | 「在某月某日那会儿」的取值 |
| temporal_order | 两个不同项目的事件谁先被提起 |
| cross_project | 证据分布在两个及以上项目，需要连起来 |
| disambiguation | 同名人物／同一词在不同项目指不同东西 |
| zero_overlap | 与证据零词面重叠的改写问句 |
| abstention | 从未提及（不计检索分；可用于作答拒答） |

## 格式与口径
- LoCoMo 风格：`[{sample_id, conversation{speaker_a, speaker_b, session_N, session_N_date_time}, qa[...]}]`，轮次 `dia_id = DN:k`。
- 每题：`evidence`（植入轮）、`evidence_events`（真值事件）、`evidence_groups`（每个事件一组：植入轮 + 该版本有效期内原样复述同一取值的轮）。
- 主指标 r@10：每个证据组命中组内任一轮即覆盖；r@k = 覆盖比例，all@k = 全部覆盖。见 `score.py`。
- hold 在交付记忆bench 前封存，sha256 见 `release/SHA256SUMS.json`；调参只用 dev。

## 已知局限
- 单人物、单一叙事，题目间不独立（有效样本量小于题数）。
- temporal_order 依据「先被提起」（会话日期），不是事件本身发生日期。
- 合成对话；版权归用户，可自由使用。
