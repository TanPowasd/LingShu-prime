# crossproj-zh-dialog v0.1 数据卡

SPDX: LicenseRef-TanPowasd-Proprietary。用途：只作正文日期 v0.2（`vsa/PREREG_body_date_v0.2.md`，L1 vs BD2）的保留集之一，**只跑一次**。
本数据与生成器在 PREREG v0.2、任何 v0.2 实现与任何 v0.2 读数**之前**冻结提交（用户 2026-10-22 00:57 指定顺序）。

**一句话**：四个互不相干的人物（纪录片导演 / 桥梁工程师 / 中学语文老师 / 餐厅主厨）各一个记忆库，每库 40 个单元 = 24 段与「AI助手」的长对话记录（> K_MAX，多日期）+ 16 条短记录；
共 160 单元、176 题。形态仿 PerLTQA 对话记录：首行「YYYY年M月D日 hh:mm:ss」，其后「说话人:话语」逐行、用户与 AI助手交替（说话人与冒号之间无空格）。

## 生成方式
- `gen.py`：**零 LLM、零 key**，标准库模板生成，固定种子 **20261023**，确定性（重跑同一 sha256）。不 import `vsa/` 任何模块，不读任何算法输出。
- 新生成器、新人物 / 对象 / 属性 / 事件表、新句式；不复用 crossproj-zh-long（20261021）与 crossproj-zh-bodydate（20261022）生成器的代码路径与题面模板。
- 真值：库内 对象 × 属性 取值唯一、对象 × 事件 唯一；取值（人名 / 机构 / 地点 / 数量）库内全局唯一（地点也供短记录事件使用，同一取值池）。
- 日期：库内各单元首行日期互不相同（全在 2026 年，约 6.5 天一段）；单元内所有日期的**年份互不相同**（年粒度金标在单元内唯一）；正文事件日期 2010–2025 年。
  全文只出现「YYYY年」「YYYY年M月D日」两种时间表达（结构校验断言：句内时间只能解析为 YEAR / DATE）。

## 处理口径（读数脚本须照此；写在冻结前）
PerLTQA 口径（`seg_real.run_perltqa`）：单元载荷 `(memory.tokens(原文), seg_real.zh_time(原文))`；长单元按句切、句角色 = `zh_time(句)`（每句至多一个 TIME）。
⇒ 长单元的块角色并集可含多个 TIME（L1「干扰存疑」能出现），这是 v0.2 的 X4 唯一起作用的口径；crossproj 口径（`seg_real.cp_elems`）下 X4 不触发（推断，方案 v0.2 §2.1）。
单元 id 记作 `D<单元序+1>:1`（te 候选按 `long_hold.te_top10` 现算时用）；E1 金标单元 = `evidence`。

## 题型（176 题；每库 44）
| 类别 | 题数 | 证据 | 金标 | 设计意图 |
|---|---:|---|---|---|
| first_plain | 24 | 长对话 | 首行日期（「…是哪一天跟AI助手说的」） | 首日期类：L1 应答对的形状 |
| first_interf | 28 | 长对话 | 首行日期 | 同上，另有一段**非证据**长对话（`decoy_unit`）提到同一对象与属性（不含取值），且其前三分之一含 ≥2 个不同年份 ⇒ 预期 L1 在该候选上多 TIME 存疑、落到下一候选（是否真的存疑、是否排在证据前，冻结前未运行，存疑） |
| body_echo | 40 | 长对话 | 用户回答句里的正文日期（≠ 首日期） | AI 先问一句**问句形、无日期**的提问（`echo`），下一行用户回答含金标日期；`echo_style`：near 25（与问题近同文：「请问〈事件〉是在哪一年呢？」等 3 式）/ para 15（换说法：「您还记得〈事件〉的时间吗？」等 3 式） |
| body_plain | 20 | 长对话 | 正文日期 | 用户主动提及（无回声提问） |
| short_time | 32 | 短记录（≤ K_MAX） | 首行日期 | 短轮题；短单元不产生子痕迹 |
| fact | 32 | 长 16 / 短 16 | 取值 | 非时间检索题（只用于 E1） |

正文日期题（body_*，60 题）的陈述句式：句中式 41（日期在句中，前有说话人前缀或连接语）、句首式 19（日期作为该行第二句的句首，会开新锚点）。
每段长对话另有 1–2 句「生活日期」句（多日期来源）与大量无日期填充句（AI 泛问句含「这是什么时候的事呢？」等）。

## 结构校验（`vsa/dialog_hold.py --check`；冻结前只做这些，不跑检索 / 解绑，不 import BD 代码）
单元类型与 `seg.n_items` 一致（长 96 个，项数 375–517 > 221；短 64 个，最大 67 项）；首行为时间戳；长单元每行「说话人:话语」；长单元 ≥2 个不同日期（96/96）、单元内年份不重复；库内单元日期不重复；
题数分型 = 上表；时间题全部命中 `ZH_TIME_Q`、金标可被 `canon_zh` 解析；检索题不命中、取值只出现在证据单元；
首日期类：金标 = 首行日期，且（按问句粒度）单元内唯一；first_interf 干扰单元为另一长单元、含「对象的属性」且不含取值、前三分之一 ≥2 个日期；
正文日期类：金标在非首句出现、≠ 首日期、单元内唯一；body_echo：回声句在证据单元、问句形、无日期，下一行为用户回答且含金标日期。

## 冻结前修订记录（如实）
首版起共 4 次重新生成，**全部只为结构校验与文本自然度**，期间未运行任何检索 / 解绑 / te 候选：
1. 填充句逐字重复过多 ⇒ 单元内不放回抽取 + 新增通用填充句；事实句按取值类型换句式（「片长找的是 71 分钟」类不通顺句）；干扰句两句不同模板。
2. 人名「周一鸣」被解析为星期（`zh_time` 命中「周一」）⇒ 删去名「一鸣」。
3. 回声句 near / para 由 1:1 调为约 65% near（用户要求「与问题近同文」）。未计算任何相似度（未算二元组 Jaccard），未按 E2 的 τ 挑选句子。
4. 短记录地点与事实取值撞车（`dg082`）⇒ 短记录地点改走取值池。

## 功效估算（推断，冻结前写）
- 正文日期类 60 题：金标 ≠ 首日期且单元内唯一 ⇒ L1（单元级只解出首日期或存疑）预期 ≈ 0 对（除非存疑落到别的候选碰巧对）。
  BD2 胜 ≈ BD2 在正文类的正确数。若 BD2 正文类 ≥ 25%（15 胜）且他类负 ≤ 4 ⇒ 15/4 符号检验 p ≈ .019；10 胜 / 1 负 ⇒ p ≈ .012；10/3 ⇒ p ≈ .09（检出边界）。
- 首日期类 52（长）+ 32（短）题：严格读法下 L1 答对的每一题 BD2 都不得答错；52 道长对话首日期题能暴露 B-iii 锚点漂移（事实句继承了行内句首年份）与 X4 放行错误候选两类伤害，单题即可判负。

## 已知局限（存疑）
- **生成器与评测方同源**：模板、题型与金标规则出自实现 BD / v0.2 的同一方，编写者已看过 v0.2 的 dev 诊断（问句回声、干扰存疑两类失败）；
  body_echo 与 first_interf 正是为这两类机制写的形状 ⇒ 本集通过只能说明「机制在同源合成对话上按设计工作」，不等于真实数据上的收益。
- 模板中文规整、复述少、日期表达只有两种；问句与证据句词面重合高（近同文回声尤甚）。
- 干扰候选是否真的使 L1 存疑、是否被 te 排到证据前面，冻结前未验证（不运行任何算法）；读数时如实报告触发数。
- 四库、每库单一叙事，题目间不完全独立；部分组合语义不自然（如「毕业纪念册的经费」）。
- 未覆盖：相对日期、一句两个日期、月粒度、英文。
