                    │ 插件清单 Manifest · 宿主上下文 Context · 一致性测试          │
                    └───────▲───────────────────────────────────────▲─────────────┘

      ┌─────────────────────┴───────────┐           ┌───────────────┴──────────────────┐

- 统一接口不另起炉灶：大脑库的 `cg(op, action, …)` 已是「认知图唯一入口」（约 42 个 op，`principal.require_op` 做角色闸），身体库世界方法已收敛为 `fn(action, params)`，身体侧 `brain_store` 已经用 `client.call("cg", {"op": …})` 调大脑。把这个信封正式化，两边共用。
- 拆分后每个包有自己的版本、测试、待办；首轮迭代待办直接取各包已有的开放 issue（§3、§4 每包列出）。

## 2. 统一接口（所有拆分任务都按它验收）

### 2.1 调用信封
```python
call(op: str, action: str | None = None, **args) -> dict
# 返回必含 "status"（"ok" 或具体原因，如 "voxel_not_ready"）；大脑侧兼容现有 "ok"/"error" 字段
```
- `op` ＝能力名（插件提供），`action` ＝能力内动作。与 `cg` 现行语义一致：op 缺省时按参数签名推导的规则保留在大脑宿主内，不进公共接口。
- 身体侧映射：`engine.voxel_world(action, params)` ≡ `call("voxel", action, **params)`，旧方法保留为薄壳。

### 2.2 插件清单 `Manifest`
| 字段 | 含义 |
|---|---|
| `name` / `version` | 包名、SemVer |
| `api` | 兼容的 lingshu-api 区间，如 `>=1,<2` |
| `provides` | 提供的 op 列表 |
| `requires` | 依赖的 op（只按能力名，不按包名） |
| `writes` | 允许写入的层（身体：CONTEXT/KNOWLEDGE；大脑：contextual/knowledge …），宿主据此授权 |
| `permission` | 需要的角色/op 权限（大脑：`require_op` 名；身体：`Role`） |
| `extras` | 重依赖声明（numpy、Pillow、torch …） |

### 2.3 宿主上下文 `Context`
- `read` 只读视图；`write(...)` 必经宿主写入闸；`emit/subscribe` 事件；`capability(op)` 只对 `requires` 内的 op 返回句柄，否则 `None`。
- **身体宿主**实现：写入走 `Provenance` 契约 + `LongTermMemoryGate` 定层 + `add_node` 的 Role/`IMMUTABLE_LAYERS`。
- **大脑宿主**实现：写入走现有 `writepipe` 默认链（审核 ACCEPT/REJECT/DEFER、冲突检测、autonomy 档位闸），权限走 `principal.require_op`。
- 两边的写入闸都**复用现有机制**，lingshu-api 只规定接口，不规定策略。

### 2.4 传输
- 同进程：直接调用。
- 跨进程：MCP。大脑已有 `cg`/`stg` 工具；身体侧新增对称的 `body` 工具（同一信封）。`brain_store` 现有调用方式不变。

### 2.5 一致性测试（每个插件包必须过）
清单合法；越权写被拒；缺依赖时返回 `*_not_ready` 而不抛；返回体含 `status`；卸载后宿主自身测试读数不变；插件间零直接 import（AST 门禁）。

### 2.6 需要先对齐的两处命名冲突
| 名称 | 身体库含义 | 大脑库含义 | 处理 |
|---|---|---|---|
| provenance | 观测来源契约（条件空间四栏 + 验证状态） | 派生血缘（`derived_from` 台账） | 写入记录同时携带两者，字段名分开：`observation` / `lineage` |
| 层名 | ANCHOR / STRUCTURE / KNOWLEDGE / CONTEXT / SELF | anchor / structure / knowledge / contextual … | U3 出对照表，接口层用统一枚举 |

### 4.3 M0 首轮校准读数（`_cg_dispatch` 实读，baab3a1）

## 附录 A · import 图脚本

```python
# 在 md_cg/ 或 lingshu/lingshu/<pkg>/ 下运行：统计本包模块间直接 import
import ast, os, collections
mods = {f[:-3] for f in os.listdir('.') if f.endswith('.py') and not f.startswith(('test_', 'bench'))}
deg = collections.Counter(); out = {}
for m in mods:
    t = ast.parse(open(m + '.py', encoding='utf-8').read()); deps = set()
    for n in ast.walk(t):
        if isinstance(n, ast.ImportFrom):
            base = (n.module or '').split('.')[-1]
            if base in mods: deps.add(base)
            if not n.module or n.module.endswith('md_cg'):
                deps |= {a.name for a in n.names if a.name in mods}
        elif isinstance(n, ast.Import):
            deps |= {a.name.split('.')[-1] for a in n.names if a.name.split('.')[-1] in mods}
    deps.discard(m); out[m] = deps
    for d in deps: deg[d] += 1
print(deg.most_common(15))
```
