## 1. 核心主张：一个底座，多个插件，单向依赖

```
            ┌──────────── 插件（独立 pip 包，可选）────────────┐
            │ lingshu-world  lingshu-nn  lingshu-gen  第三方…   │
            └───────┬─────────────▲──────────────────────────────┘
       能力调用/事件 │             │ 只经 CognitionContext 读写
            ┌───────▼─────────────┴──────────────────────────────┐
            │ lingshu-core（底座＝统一认知）                       │
            │ 认知图 STNode/STEdge · ConditionSpace · provenance   │
            │ 写入闸（零 LLM 落库）· time_core · verdict · 事件总线 │
            │ 插件注册表 Registry · 能力路由 · 版本协商              │
            └────────────────────────────────────────────────────┘
```

- **统一认知** = 所有插件共享同一张认知图、同一条件空间、同一写入闸与溯源规则；插件不各自存一份世界。
- **解耦** = 插件之间零 import、插件对底座只依赖公开协议；底座**永不 import 插件**（CI 门禁）。
- **可选安装** = 每个插件是独立分发包，经 entry points 被发现；没装就是「能力不存在」，不是报错。

## 2. 五个标准件

### 2.1 插件清单 `PluginManifest`
```python
@dataclass(frozen=True)
class PluginManifest:
    name: str                 # "world3d"
    version: str              # 插件自身 SemVer
    lspi: str                 # 兼容的协议区间，如 ">=1,<2"
    provides: tuple[str, ...] # 能力名，如 ("world3d.build", "world3d.render")
    requires: tuple[str, ...] = ()   # 依赖的其他能力（只按能力名，不按包名）
    reads:  tuple[str, ...] = ()     # 读哪些节点类型/层
    writes: tuple[str, ...] = ()     # 写哪些节点类型/层（写入闸据此授权）
    extras: tuple[str, ...] = ()     # 声明重依赖，供安装提示与审计
```

### 2.2 插件协议 `LingshuPlugin`
```python
class LingshuPlugin(Protocol):
    manifest: PluginManifest
    def activate(self, ctx: "CognitionContext") -> None: ...
    def call(self, action: str, params: dict) -> dict: ...   # 沿用现有签名
    def deactivate(self) -> None: ...
```

### 2.3 认知上下文 `CognitionContext`（统一认知的唯一入口）
- `ctx.read`：只读视图（query_nodes / traverse / spatiotemporal_query …）
- `ctx.write(node|edge, condition=..., evidence=...)`：**必经写入闸**——自动打 `provenance = plugin://name@version`、校验 `manifest.writes`、条件显式、零 LLM。
- `ctx.emit(event)` / `ctx.subscribe(type, handler)`：复用引擎现有 notify_event/consume_events。
- `ctx.capability(name)`：按能力名拿别的插件，拿不到返回 `None`（不抛异常）。

### 2.4 发现与注册
- 分发包在 `pyproject.toml` 声明 `[project.entry-points."lingshu.plugins"] world3d = "lingshu_world.world3d:Plugin"`。
- 底座用 `importlib.metadata.entry_points(group="lingshu.plugins")` 发现，按 `lspi` 区间协商，`requires` 拓扑排序后激活；冲突/缺依赖写入 `engine.plugins.report()`，不静默。

### 2.5 一致性测试包 `lingshu.testing.conformance`
每个插件必须通过：清单合法、未声明写入被闸拒、缺依赖时优雅降级、`call` 返回体含 `status`、卸载后底座测试全绿。上游「能被独立复跑」的纪律因此对第三方插件同样成立。

## 3. 向后兼容（不破坏现有调用方）
- `engine.world3d(action, params)` 等 38 个方法保留为**薄壳**：`return self.plugins.call("world3d", action, params)`；插件缺席时仍返回原来的 `{"status": "world3d_not_ready", ...}`。
- 新入口：`engine.cap("world3d").call("build", {...})`、`engine.plugins.list()`。

## 4. 与上游聚合原则的关系
上游坚持「单一聚合仓」。本框架**不要求拆仓**：monorepo 内多个分发包（`packages/lingshu-core`、`packages/lingshu-world`…），聚合仓仍是唯一真源，`pip install lingshu[full]` 仍一键装全；只是每件也能单装。
