# AGM × hive-memory-bench · 检索面基准

用 [hive-memory-bench](https://github.com/FuRongJun-1999/hive-memory-bench)（符荣峻；代码 MIT，语料与答案键 CC BY 4.0）
测 AGM v0.5 的**检索面**。本目录只放我们自己的脚本与读数，不复制该基准的语料和答案键，运行时从它的仓库读取。

```bash
git clone https://github.com/FuRongJun-1999/hive-memory-bench    # 读数基于 72130ac
python TanPowasd/agm/bench/hive_retrieval.py hive-memory-bench --json TanPowasd/agm/readings_bench_hive_retrieval.json
```
依赖：Python 3.12 + PyYAML；零 LLM、零网络，约 2 秒。

## 测的是什么、不是什么

hive-memory-bench 的正式成绩要「检索 → 外部生成器作答 → ≥2 个 LLM 判官判分」。我们手上没有生成器和判官，所以**只测它不依赖 LLM 的那一段**：
主轮 92 题答案键里，每题都标了答题要用的证据句（`supporting_evidence`，分 primary / corroborating）和误用片段（`must_exclude`）。
同一份语料、同样切块（约 160 字一块，共 303 块、50,815 字）、同样字数预算下，看每个检索器交出的上下文里**证据句完整保住了几句**。

| 臂 | 做法 |
|---|---|
| BM25 | 字二元组 BM25。与基准里的「朴素 BM25」同类，**不是**它的原实现 |
| AGM | BM25 取 8 个种子 → 在联想图上扩散 2 步。图：同章相邻块的时序边（前向 0.5、后向 0.25）+ 共享术语的联想边（非对称：i 的术语有多少在 j 里，每块最多 8 条），跨 ≥3 章复现的术语给边加固化权重；放电阈值 0.04，k-WTA 60 |
| AGM+反射 | AGM 再加非条件关键词反射（v0.6 §4D）：题面里的显著二元组按习惯化增益 `1/(1+ln(1+df))` 直接点亮含它的块，归一化 ≥0.5 的作为额外种子 |
| AGM-退火 | 同上，扩散时弱边按 `1 − exp(−w/T)`（T=0.3）的概率才放行，5 个种子平均 |
| 随机 | 随机取块，下限 |

四臂交出的都是原文切块，逐字率恒为 100%，不单列。

## 结论

1. **AGM 与 BM25 打平，没有显著差异。** 三档预算的配对符号检验 p 都在 0.6 以上。
2. **8000 字档 AGM 略好，但样本太小不能下结论**：全证据题 8/38 对 5/38，跨章题 4/32 对 1/32。方向和设计意图一致（联想边能把另一章的那一块带进来），要更大题集才能确认。
3. **退火对一次性检索没有帮助**，甚至略差。符合预期：§4C 的退火是靠「反复走、走通就加强」起作用的，这个基准每题只检索一次，没有学习环节。
4. **非条件关键词反射是负结果**（v0.6 加测）：8000 字档比 AGM 少保住证据，逐题 2 胜 13 负，p=0.007，是全表唯一显著的差异。题面关键词点亮的块中位 8 块、最多 32 块，其中含证据的只占 9.2%（BM25 前 8 名是 12.8%），把预算挤掉了。反射得靠使用历史学出来（条件反射），这个基准每题只问一次，测不到。
5. **AGM 带入的误用片段略多**（4000 字档 0.375 对 0.328）：扩散会把相关但不该用的块一起带进来。

## 局限

- **只测检索面，与基准官方成绩不可比**：官方数字是答题后由判官判的通过率；
- 主轮答案键已公开，题目也不独立（基准自己的分析：有效样本量 ≤24）；
- AGM 的核心优势（反复使用后的固化、捷径、方向学习、睡眠重放）这里都没用上：图是一次建好的，没有使用历史；
- 参数敏感性（8000 字档，联想边下限 × 每块出边数）：0.2×4 → primary 0.491；0.12×8（默认）→ 0.522；0.06×8 → 0.474。默认值是在看读数之前定的，但它恰好最好，所以 0.522 要按偏乐观理解；
- 干预轮、端到端真实史轨都需要生成器和判官，没跑。

# 真实对话史轨（e2e）· 流式续接支撑（2026-10-10）

上面的主轮每题只问一次，AGM 的学习部件测不到。这一节换到基准的 `e2e/` 真实史轨（16 份对话、8,146 轮），**让系统按时间顺序边读边学**。

```bash
python TanPowasd/agm/bench/hive_e2e_stream.py <hive-memory-bench 路径> --parts 固化,反射,赫布   # 消融：--parts 固化 / 反射 / 赫布
```
原始读数：`agm/readings_bench_hive_e2e.json`。纯标准库，四种部件配置并行约 3 分钟。

## 测法（零 LLM 代理读数，**不是**官方 C 型判分）

- 每份对话从空记忆开始；对每个「我说」轮，用这句话作查询，从**此前全部历史**里取 4,000 字上下文；
- 评分：AI 紧接着的真实回复里的显著二元组（本文件内只在 ≤2% 的块里出现），扣掉查询本身已有的之后，有多少比例出现在取到的上下文中——即「历史给这次回复提供了多少额外支撑」；
- 评分**之后**才学习：回复里真正用上的取回块（与回复共享 ≥3 个显著二元组）得到强化。不存在偷看下文；
- 另在 87 张 C 型题卡的断点处（截断到答案行之前），以题卡的 pre 轮作查询，对「人类下一句 + AI 恢复开头」同法打分。

被测臂：最近窗口（直接取断点前最近 4,000 字）、BM25、AGM-静态（BM25 种子 + 时序边/对话邻接边扩散，不学习）、AGM-学习（静态 + 选定的学习部件）。

## 读数（4,041 个查询轮；87 张题卡）

|---|---:|---:|
| 最近窗口 | **0.1450** | 0.1386 |
| BM25 | 0.1397 | 0.1412 |
| AGM-静态 | **0.1448** | **0.1422** |
| AGM-学习：仅使用固化 | 0.1443 | 0.1419 |
| AGM-学习：仅赫布边 | 0.1447 | 0.1422 |
| AGM-学习：仅条件关键词反射 | 0.1158 | 0.1144 |
| AGM-学习：三者全开 | 0.0905 | 0.1033 |

逐轮配对：
| 比较 | 胜 / 负 / 平 | 符号检验 p |
|---|---|---|
| AGM-静态 对 BM25 | **2065 / 1590** / 386 | <0.0001 |
| BM25 对 最近窗口 | 1887 / 2000 / 154 | 0.072 |
| 固化 对 AGM-静态 | 722 / 750 / 2569 | 0.48 |

题卡配对（87 张）：AGM-学习全开 对 AGM-静态 14 胜 51 负（p<0.0001）；BM25 对 最近窗口 38 胜 29 负（p=0.33）；仅固化 / 仅赫布 对 静态几乎全平。

## 结论

1. **AGM-静态显著胜 BM25**（逐轮 2065 胜 1590 负），这是 AGM 在本基准上第一个显著正结果。来源是对话结构边：查询命中一块，时序边和「问→答」邻接边把同一轮、下一轮的块一起带进来。
2. **但它只追平最近窗口**（0.1448 对 0.1450）。在这个代理指标上，「接着往下聊」最近的历史就是很强的基线；BM25 还略输于它（p=0.07）。下一步应测「最近窗口 + AGM 联想」混合预算。
3. **使用固化、赫布边：中性**。大多数轮完全打平——被用上的块在之后的轮里很少再被需要，话题在往前走。
4. **条件关键词反射：显著负结果**，三部件合开更差（交互作用）。第一版还发现一处设计冲突并已修正：习惯化若对所有出现计数，增益在第 3 次就降到 0.42，条件反射永远到不了 0.5 阈值；改为只数「出现了却没有后果」的次数（§4D.3 原意）。修正后反射能放电，但放电的是**旧话题的块**：真实对话里一个词今天指向的内容，往往不是它上次指向的。
5. 赫布边第一版没设上限（权重到 1.0、无出边预算）时，把共用块连成团、逐轮支撑从 0.154 掉到 0.125；加上限 0.3、每次只连最相关 3 块、出边预算 8 之后转为中性。这和 v0.4 的稳态问题是同一类：**局部强化必须配全局约束**。

## 局限

- 「显著二元组覆盖」只是代理指标，量的是取回内容与真实下文的词面重合，不等于官方 C 型的要素命中，更没有依据轴回源判分；
- 「被用上」用词面重合判定（≥3 个显著二元组），是很粗的奖励信号，条件反射的负结果有一部分可能来自这个噪声；
- 每份对话各自从零开始，没测跨会话续接（基准原意的「上下文超限 → 重新接入」）；
- 第一版跑完后改过两处（习惯化计数口径、赫布上限），之后没再调参；四种部件配置用的是同一套参数。

# e2e v2：三项改进（2026-10-10）

```bash
python TanPowasd/agm/bench/hive_e2e_v2.py <hive-memory-bench 路径> --mix 0.5     # 0.25 / 0.75 为近因比例扫描
```
原始读数 `agm/readings_bench_hive_e2e_v2.json`。测法、数据、切块、评分与上一节完全相同。

改了什么：
1. **双通道预算**：近因通道固定取最近 r×4000 字，联想通道（BM25 或 AGM）在剩余预算里取，跳过窗口里已有的块；
2. **学习信号**：一块的功劳＝回复里只有它提供的显著二元组（留一法），独占 ≥2 个才算「有用」；调制项 M＝有用 − 该块的预期有用率（预测误差），固化 s += M；
3. **反射**：（关键词, 块）强度按 Rescorla–Wagner 向「是否有用」靠拢，读出时乘 exp(−Δ轮/60) 和习惯化增益，只在已激活候选里加分，不再当种子。

## 读数（4,041 轮 / 87 张题卡）

|---|---:|---:|---:|---:|
| 最近窗口 | 0.1450 | 0.1450 | 0.1450 | 0.1386 |
| AGM-静态（单通道） | 0.1448 | 0.1448 | 0.1448 | 0.1422 |
| AGM-学习v2（单通道） | 0.1446 | 0.1446 | 0.1446 | 0.1450 |

| 近因+AGM-静态 | **0.1549** | **0.1562** | **0.1540** | 0.1529 |
| 近因+AGM-学习v2 | 0.1545 | 0.1560 | 0.1539 | 0.1515 |

逐轮配对（r=0.5）：
| 比较 | 胜 / 负 / 平 | p |
|---|---|---|
| 近因+AGM-静态 对 最近窗口 | **2252 / 1462** / 327 | <0.0001 |
| 近因+AGM-静态 对 近因+BM25 | **1279 / 1074** / 1688 | <0.0001 |
| AGM-学习v2 对 AGM-静态 | 1229 / 1188 / 1624 | 0.42 |

题卡（r=0.5）：近因+AGM-静态 对 最近窗口 37 胜 17 负（p=0.009）；对 近因+BM25 17 胜 19 负（p=0.87）。

## 结论

1. **双通道是本轮最大的改进**：r=0.5 时逐轮支撑 0.1450 → 0.1562（+7.7%），显著胜最近窗口，也显著胜同结构的「近因+BM25」，但均值只高 0.0012。r=0.5 是事先定的默认值，扫描里它也恰好最好，峰值较平（0.25 和 0.75 都在 0.154 以上）。
2. **新学习信号把负结果修到了中性**：上一版条件反射是 653 胜 2813 负，v2 单通道变成 1229 胜 1188 负，不再伤人；但也**还没有学出正收益**，双通道里甚至略负（均值差 0.0002，p=0.007）。
3. 题卡上 BM25 和 AGM 打平（87 张，样本小）。
4. 判断：在每份对话从零开始的设定里，「将来还会被需要的旧块」太少，学习没有东西可学。下一步要换到**跨会话续接**（把前一份对话的记忆带进下一份），并按事先定好的方式把文件分成调参集和测试集。

## 更正：按文件做检验（2026-10-10）

同一份对话里的各轮并不独立，逐轮符号检验会把 p 值算得过小。改成以 16 份对话为单位（每份取均值，再做符号检验）：

| 比较（r=0.5） | 文件胜 / 负 | p |
|---|---|---|
| 近因+AGM-静态 对 最近窗口 | 15 / 1 | 0.0005 |
| AGM-静态 对 BM25 | 15 / 1 | 0.0005 |

所以：双通道胜过纯窗口、AGM 结构边胜过 BM25，这两条站得住；**「近因+AGM 胜过近因+BM25」不能宣称**，上面 v2 结论第 1 条以本表为准。
