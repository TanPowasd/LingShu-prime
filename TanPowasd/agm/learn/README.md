# 自主学习 Learn（记忆四能力套件 · 自主学习）

零模型、零网络、零判官。从已经懂的句子里自举学会新说法：已知槽「主体 的 属性」+ 已知取值池 ⇒ 未知连接词是一种「改成」；在 ≥2 个不同槽上出现且取值落池才晋升，晋升后整库重放巩固，迭代到不动点。`learn_until` 前学后测，不偷看未来。

## 复跑
```bash
python -X utf8 bench_learn.py <hive-memory-bench>                 # 混合扰动 p=.5，3 个扰动种子，~7s
python -X utf8 bench_learn.py <hive-memory-bench> --p 1.0         # 全部换成表外说法
python -X utf8 bench_learn.py <hive-memory-bench> --corpus-seed 7 # 生成器新种子语料（保留集）
python -X utf8 test_learn.py            # 守卫 9 条
python -X utf8 test_learn.py --mutate   # 定点变异 6 条
```

## 边界
- 扰动替换词表是我写的，学习器和扰动都出自同一侧；真实口语的说法更散，未测。
- 只学「改成」类与隐含属性类；撤销、两说并存、裁定类的新说法不学。
- 取值校验在本语料上偏保守（.986 vs 不校验 .997），本语料没有能骗过槽数门的噪声，所以它的防护作用只在守卫 L4 里被证明，没在基准里体现出收益。默认值未按本读数调整。
- 学习要求句中带空格分隔值，或值本身已在取值池里（逐位试切）。

## 外部考卷：Liyang 的零 LLM 改写规则（2026-10-13）
`bench_external.py` 只读 `Liyang/bench_chain/perturb.py` 的改写表与改写函数（他人独立编写，不改 Liyang/）。soft＝换动词（含撤销/并存/裁定句）；hard＝主体挪到属性后、句首换话题标记。「存盘表」＝在生成器 seed=7 语料上同规则学到的说法，载入官方语料后不再学（跨语料保存）。全部题型完全正确率：

| 设置 | 冻结 | Learn | 存盘表 | 存盘表+Learn |
|---|---|---|---|---|
| soft ×.5 | .553 | .807 | **.815** | .815 |
| soft ×1.0 | .140 | .170 | .326 | **.606** |
| hard ×.5 | .498 | .536 | .536 | .536 |
| hard ×1.0 | .019 | .019 | .019 | .019 |

- 先跑出的版本（`results/external_liyang_perturb_prefix.json`）暴露一个推理侧 bug：「改成了 V」被已有动词「改成」吃掉，值里多了「了」。修正（`_value` 去掉动态助词）后才是上表；修正后 hive chain 原读数与全部守卫不变。这是看过外部考卷后的事后修正，照实记。
- soft ×1.0：全部事件句都换了说法，本语料几乎没有种子槽，单靠自学 .170；带上别的语料存下来的说法，种子回来了，再自学到 .606。这是「学得越多越好」唯一成立的场景。
- 时点、变更两类基本不动：撤销/两说并存类的新说法不学。
- hard 改写完全学不会：句子不再是「主体 的 属性」形状，学习器找不到已知槽。这是结构上的边界，不是数据量问题。

## 句框 + v15 老师 + 干净考法（2026-10-13）
新增两件事（都零模型）：
- **句框**（`frames=True`）：没抽出事件的句子 → 把主体换 ⟨S⟩、属性换 ⟨A⟩、截到取值前得到整句骨架（如「说到⟨A⟩，⟨S⟩ 这回定为」）；≥2 个不同槽共用同一骨架才晋升。推理侧 `Reason(frames=…)` 按骨架抽取；多个说法都能匹配时取属性最短的切法（修「最早定|成了」被短动词「成了」吞掉）。
- **老师**（`teacher="v15"`，`teacher_v15.py`）：只读调用 Liyang/lingshu_ng 的零 LLM 版本链抽取 v15，把它会抽、本模块不会抽的句子当对齐样本归纳句框（含撤销/并存/裁定的动作）。运行期不依赖 v15：学到的句框随说法表存盘。

用户指出「学完考题再用考题考」：上面外部考卷里学习器读的就是被考的那批改写句（不读题和答案，但同分布）。`bench_clean.py` 改成三种学习时看不到被考句子的考法，只有它们算成绩（全部题型完全正确率，`results/clean_exam.json`）：

| 考法（官方语料 ×1.0 全改写） | 冻结 | 自学 | +句框 | +句框+v15 |
|---|---|---|---|---|
| B 跨语料：seed7 学 soft → 考 soft | .140 | .326 | .326 | **1.000** |
| B 跨语料：seed7 学 hard → 考 hard | .019 | .019 | .019 | **.852** |
| A 跨规则：学 hard → 考 soft | .140 | .140 | .140 | .140 |
| A 跨规则：学 soft → 考 hard | .019 | .019 | .019 | .019 |
| C 前学后测 soft（只学前半程，考后半程 415 题） | .116 | .130 | .130 | **.819** |
| C 前学后测 hard | .000 | .000 | .000 | **.735** |

- 没有老师时，自举在干净考法下几乎学不到东西：全改写语料里没有可认的种子槽。之前 .986/.998 的读数来自混合扰动（一半句子仍是原说法，种子充足）。
- 跨规则迁移为零：学到的是具体说法和骨架，不是「状态变更」的概念；换一套写法就要重新学。这是当前方法的硬边界。
- 老师臂的提升要打折看：v15 与改写规则同出 Liyang 之手，v15 可能针对这套规则调过。hard 的时点/变更 .603（B）偏低是信息本身丢了：hard 把建立/调整/并存/裁定都改成「这回定为」。
- 同语料参照（D，不算成绩）：soft +句框+v15 1.000，hard .852。

## LLM+ 模式（可选插件，默认关闭）

默认仍是零 LLM、零网络。`Learner(llm=teacher_llm.Teacher())` 打开 LLM+：
- 只有表/句框认不出、或认出了但没把整句解释全（主体前有多余内容、取值里带分句标点）的句子才问 LLM；回顾句、改名句不问。
- LLM 只抽 主体/属性/动作/取值/第二取值/原因；主体、取值、原因须逐字出现在原句，属性没写出时只认记忆里已有的属性名。
- 问到的结果先做句框自检（用骨架重抽原句，须与老师标注一致），≥2 个槽共用才晋升为新句框，之后同句形不再问；学不成句框的写成规范句直接入链。句框可 `lexicon()` 存盘，之后冻结载入零调用。
- 提示词不含任何基准属性名或例句；接口为任意 OpenAI 兼容 chat/completions：`LEARN_LLM=1`（必需）、`LEARN_LLM_URL`、`LEARN_LLM_MODEL`、`LEARN_LLM_KEY`。磁盘缓存 `cache_llm/`（不入库）。

泛用性考法 `bench_llmplus.py`：LLM 自由改写官方语料的事件句（句式逐句变化，名字/取值逐字保留，与 Liyang 规则和我们的扰动词表无关），保留集存 `results/paraphrase_llm*.json`。

| 保留集 | 题数 | 冻结 | 冻结+v15说法表 | LLM+ 冷启动 | LLM+ 调用 |
|---|---|---|---|---|---|
| 青石镇+猎户项目（开发时反复看过，偏乐观） | 214 | .257 | .266 | .944 | 8 |
| 雾港+孤山驿+流明+织女（定稿后才跑，未调参） | 428 | .213 | .213 | **.935** | 16 |

未调参保留集分题型：现值 .976、时点 1.000、历史 .937、变更 .690、缘由 .952、状态归属 .970。变更最弱（整条链任一事件漏抽即错）。
注意：改写用的是同一个模型族（deepseek-v4.1-flash），改写者与抽取者同源，可能偏乐观；真人改写未测。
